### 1. Зачем заимствование

Если бы Rust позволял использовать только перемещения (move), то код был бы крайне неудобным: каждую переменную нужно было бы передавать во все функции и возвращать обратно. Например:

```rust
fn main() {
    let s = String::from("hello");
    take(s);
    take_again(s); // ошибка — s уже недействителен
}
```

Нужна возможность **временно «одолжить» данные**, не отдавая их полностью. Именно это делает заимствование.

---

### 2. Ссылки (`&`)

Rust вводит ссылки на значения.

```rust
let s = String::from("hello");
let r = &s; // r — ссылка на s
```

– `r` **не владеет** данными,  
– `r` **не может** изменить владение или вызвать drop,  
– `s` продолжает быть владельцем.

Ссылки бывают двух видов:

1. **Immutable (неизменяемые)** – `&T`
    
2. **Mutable (изменяемые)** – `&mut T`
    

---

### 3. Правила заимствования

Rust компилятор строго следит за безопасностью и накладывает два ключевых правила:

1. В один момент времени может быть **любое количество неизменяемых ссылок `&T`).  
    Пример:
```rust
let s = String::from("hello");
let r1 = &s;
let r2 = &s;
println!("{} and {}", r1, r2); // ок
```

2. В один момент времени может быть **только одна изменяемая ссылка** (`&mut T`) и **ни одной другой ссылки**.  
    Пример:
    
```rust
let mut s = String::from("hello");
let r = &mut s; // ok
let r2 = &mut s; // ошибка — уже есть mutable ссылка
```

– Эти правила предотвращают гонки данных и use-after-free на этапе компиляции.

---

### 4. Mutable и immutable вместе

Вы не можете одновременно иметь mutable и immutable ссылки:

```rust
let mut s = String::from("hello");
let r1 = &s;        // immutable
let r2 = &mut s;    // ошибка — нельзя иметь & и &mut одновременно
```

Компилятор запрещает это, потому что иначе можно было бы менять данные через `r2`, пока `r1` читает старое значение — data race.

---

### 5. Заимствование в функциях

Ссылки позволяют безопасно передавать данные в функции **без передачи владения**:

```rust
fn print_length(s: &String) {
    println!("{}", s.len());
}

let s = String::from("hello");
print_length(&s); // владение не передаётся
println!("{}", s); // s всё ещё валидна
```

Для изменения данных:

```rust
fn append_world(s: &mut String) {
    s.push_str(", world");
}

let mut s = String::from("hello");
append_world(&mut s);
println!("{}", s); // "hello, world"
```

---

### 6. Жизненные циклы ссылок (lifetimes)

Ссылки живут **не дольше владельца**, иначе Rust не разрешит код.  
Это предотвращает висячие ссылки:

```rust
let r;
{
    let s = String::from("hello");
    r = &s; // ошибка — s выйдет из scope, r станет dangling
}
```

Компилятор не даст скомпилировать. Lifetimes — это способ описать компилятору **жизненный цикл ссылок**, чтобы он мог проверять безопасность на этапе компиляции.

---

### 7. Ключевая мысль

Заимствование — это **безопасное «одалживание» данных без передачи владения**.

– Immutable ссылки позволяют читать данные,  
– Mutable ссылки позволяют изменять,  
– Компилятор гарантирует отсутствие гонок и dangling references.

Именно сочетание **владения + заимствования** даёт Rust уникальную гарантию безопасности памяти **на этапе компиляции** без GC.
