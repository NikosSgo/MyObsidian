В любом языке с ручным управлением памятью есть три фундаментальных вопроса:
1. кто владеет данными;
2. когда эти данные можно использовать;
3. когда их нужно освободить.

#### 1. Что значит «владение» в Rust

В Rust **каждое значение имеет ровно одного владельца** (owner).
Владелец:  
– отвечает за время жизни значения,  
– освобождает память, когда выходит из области видимости.

Простейший пример (концептуально):

`let s = String::from("hello");`

Переменная `s` — владелец строки. Когда `s` выходит из scope, вызывается `drop`, и память освобождается автоматически.

Никакого GC. Никакого `free` вручную. Но освобождение строго детерминировано.

#### 2. Перемещение (move), а не копирование

По умолчанию в Rust **значения не копируются, а перемещаются**.

`let a = String::from("hello"); let b = a;`

После этого:  
– владелец строки — `b`,  
– `a` больше **недействителен**.

Это не прихоть языка. Это гарантия, что:  
– нет двойного освобождения памяти,  
– всегда ровно один владелец.

Если бы Rust позволял использовать `a`, он не мог бы гарантировать безопасность без GC или runtime-проверок.

### 3. Почему примитивы «ведут себя иначе»

Типы вроде `i32`, `bool`, `f64` копируются:

`let x = 5; let y = x;`

Причина не в исключении из правил, а в trait-е `Copy`.

Типы с:  
– фиксированным размером,  
– отсутствием владения heap-памятью

могут быть побитово скопированы без риска. Это оптимизация, а не концептуальное ослабление модели.

Важно: **если тип не реализует `Copy`, он перемещается**.

### 4. Передача владения в функции

Функции подчиняются тем же правилам.

`fn take(s: String) {     // s — владелец }  let s = String::from("hello"); take(s); // s больше нельзя использовать`

Здесь владение передано функции. После вызова `take` исходная переменная недействительна.

Это может сначала раздражать, но именно это:  
– устраняет неявные alias-ы,  
– делает API честным: видно, кто за что отвечает.

### 5. Возврат владения

Если нужно передать владение обратно — это делается явно:

`fn give_back(s: String) -> String {     s }`

Rust заставляет вас **думать о жизненном цикле данных** при проектировании API. Это одна из причин, почему библиотеки на Rust часто более аккуратно спроектированы.

### 6. Связь владения и освобождения памяти

Когда владелец выходит из области видимости:  
– автоматически вызывается `drop`,  
– освобождаются все ресурсы (память, файлы, сокеты).

Это называется **RAII**, но в Rust оно жёстко зафиксировано на уровне языка, а не просто стиль.

### 7. Почему без владения невозможна безопасность

Без правила «один владелец» невозможно статически гарантировать:  
– отсутствие use-after-free,  
– отсутствие double free,  
– отсутствие висячих ссылок.

Rust сознательно запрещает целые классы программ, которые в C++ считаются «нормальными, но опасными».

### Ключевая мысль

Модель владения — это не про синтаксис.  
Это про то, что **жизнь данных становится частью типов и сигнатур функций**.

Если кратко:  
– владелец один,  
– перемещение по умолчанию,  
– освобождение — при выходе из scope,  
– всё видно в коде, а не в голове программиста.
