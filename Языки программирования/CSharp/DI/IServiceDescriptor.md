**ServiceDescriptor** — это иммутабельный контракт, определяющий правила инстанцирования сервиса в DI-контейнере. Он инкапсулирует пятиэлементную спецификацию: тип контракта (ServiceType), конкретную реализацию (ImplementationType или ImplementationFactory), готовый экземпляр (ImplementationInstance) и стратегию жизненного цикла (Lifetime). Эта структура служит атомарной единицей конфигурации, из которой контейнер строит граф зависимостей.

**Ключевая семантика** заключается в выборе одного из трёх режимов создания сервиса. Регистрация по типу (ImplementationType) позволяет контейнеру анализировать конструктор для автономного разрешения зависимостей. Фабричный метод (ImplementationFactory) предоставляет полный контроль над процессом инстанцирования, включая условную логику. Готовый экземпляр (ImplementationInstance) фиксирует объект как синглтон, исключая его из управления жизненным циклом со стороны контейнера.

**Временные характеристики** (Lifetime) определяют не только срок существования, но и область видимости экземпляра. Transient создаёт новый объект при каждом запросе, Scoped обеспечивает единственный экземпляр в рамках контекста (например, HTTP-запроса), Singleton гарантирует глобальную уникальность. Важно, что Scoped-сервисы, запрошенные из корневого контейнера, неявно преобразуются в Singleton, что может приводить к скрытым ошибкам.

**Архитектурные ограничения** дескриптора сознательны: отсутствие property injection поощряет явное внедрение через конструктор, единственный публичный конструктор устраняет неоднозначности, иммутабельность гарантирует потокобезопасность конфигурации. Эти ограничения направляют разработчика к композиции через делегаты и фабрики, а не к сложным наследственным иерархиям.

**Процесс интерпретации** происходит в две фазы. При регистрации дескриптор лишь добавляется в коллекцию без валидации графа. При первом резолве контейнер компилирует Expression Tree, преобразуя метаданные дескриптора в исполняемый делегат, который затем кэшируется для последующих вызовов. Для открытых generic-типов этот процесс повторяется при каждом новом закрытии типа.

**Эволюционная роль** ServiceDescriptor — быть минималистичным, но достаточным интерфейсом между конфигурацией и исполнением. Его дизайн отражает философию .NET Core: производительность через компиляцию в IL, безопасность через иммутабельность, расширяемость через фабрики. Когда этих возможностей недостаточно, система предлагает переход на внешние контейнеры через ServiceProviderFactory, сохраняя единый API регистрации.
