Декоратор в Python — это функция (или иной вызываемый объект), которая принимает другую функцию или метод и возвращает объект с тем же интерфейсом, но с изменённым поведением. Синтаксис @decorator эквивалентен явному присваиванию func = decorator(func), поэтому декорирование происходит в момент определения функции, а не во время её вызова.

Ключевая техническая основа декораторов — функции высшего порядка и замыкания. Декоратор оборачивает исходную функцию, перехватывая вызов и добавляя логику «до» и «после». При этом почти всегда необходимо использовать functools.wraps, чтобы сохранить имя функции, сигнатуру и документацию — без этого ломается introspection, автодокументация и отладка.

Простейший пример — декоратор логирования:

```python

from functools import wraps

def log_call(func):
    @wraps(func)
    def wrapper(*args, **kwargs):
        print(f"Calling {func.__name__}")
        result = func(*args, **kwargs)
        print(f"Finished {func.__name__}")
        return result
    return wrapper


@log_call
def process(order_id: int) -> None:
    print(f"Processing order {order_id}")

```


Здесь process на самом деле заменяется на wrapper, а оригинальная функция остаётся доступной только через замыкание. Это типичный паттерн для логирования, метрик, трассировки и контроля доступа.

Часто требуется конфигурируемое поведение. В таком случае используется параметризованный декоратор — фактически ещё один уровень вложенности:

``` python

from functools import wraps
import time

def measure_time(threshold_ms: int):
    def decorator(func):
        @wraps(func)
        def wrapper(*args, **kwargs):
            start = time.perf_counter()
            result = func(*args, **kwargs)
            elapsed = (time.perf_counter() - start) * 1000
            if elapsed > threshold_ms:
                print(f"{func.__name__} is slow: {elapsed:.2f} ms")
            return result
        return wrapper
    return decorator


@measure_time(threshold_ms=50)
def heavy_calculation():
    time.sleep(0.1)

```

Важно понимать, что measure_time(50) вызывается сразу при определении функции, а не при её выполнении. Это распространённый источник ошибок при работе с параметризованными декораторами.

Декораторы активно применяются к методам классов. При этом self передаётся только во время вызова, а не в момент декорирования:

```python

from functools import wraps

def require_active(func):
    @wraps(func)
    def wrapper(self, *args, **kwargs):
        if not self.active:
            raise RuntimeError("Object is inactive")
        return func(self, *args, **kwargs)
    return wrapper


class Service:
    def __init__(self, active: bool):
        self.active = active

    @require_active
    def execute(self):
        print("Service executed")

```


Такой подход часто используется для инвариантов доменной модели, проверок состояния и авторизации на уровне методов.

Отдельно стоит отметить порядок применения декораторов. Если декораторов несколько, они применяются снизу вверх, но выполняются сверху вниз:

``` python
@a
@b
def func():
    pass
```

Эквивалентно `func = a(b(func)).` Это принципиально важно, если декораторы управляют ресурсами, транзакциями или обработкой исключений.

В асинхронном коде декоратор обязан учитывать `async def`. Универсальные декораторы либо имеют две реализации, либо явно проверяют тип функции. Игнорирование этого приводит к нарушению семантики await.

В архитектурном смысле декораторы лучше всего подходят для сквозной инфраструктурной логики: логирование, кэширование, метрики, ретраи, безопасность. Использовать их для сложной бизнес-логики или управления жизненным циклом объектов обычно не стоит — там предпочтительнее явная композиция. Декоратор — это форма неявного расширения поведения, и его сила напрямую связана с дисциплиной применения.
