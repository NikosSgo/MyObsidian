## **1. Базовое управление дисками в Linux**

### **Идентификация дисков и разделов**
В Linux все устройства хранения представляются как файлы в директории `/dev`. Основные типы:  
- **SATA/SCSI диски** — `/dev/sda`, `/dev/sdb`  
- **NVMe SSD** — `/dev/nvme0n1`, `/dev/nvme0n1p1`  
- **Виртуальные диски** — `/dev/vda`, `/dev/xvda`

Для просмотра дисков используются команды `lsblk`, `fdisk -l`, `parted -l`. Современные системы используют **GPT (GUID Partition Table)**, которая поддерживает диски более 2 ТБ и до 128 разделов, в отличие от устаревшего **MBR**.

### **Работа с файловыми системами**
После создания разделов на них создаются файловые системы. Основные типы:
- **Ext4** — стандартная для большинства дистрибутивов
- **XFS** — эффективна для больших файлов и высоких нагрузок
- **Btrfs** — современная с поддержкой снимков, сжатия и RAID
- **FAT32/NTFS** — для совместимости с Windows

Монтирование файловых систем может быть временным (команда `mount`) или постоянным (через файл `/etc/fstab`).

## **2. RAID (Избыточный массив независимых дисков)**

**RAID** — технология объединения нескольких физических дисков в один логический для повышения надёжности и/или производительности.

### **Основные уровни RAID:**

1. **RAID 0 (Stripe)** — чередование данных без избыточности  
   - **Преимущества:** максимальная производительность  
   - **Недостатки:** отсутствие отказоустойчивости  
   - **Применение:** временные данные, кэши

2. **RAID 1 (Mirror)** — зеркалирование данных  
   - **Преимущества:** высокая надёжность, быстрое восстановление  
   - **Недостатки:** эффективная ёмкость 50%  
   - **Применение:** системы, где важна надёжность

3. **RAID 5** — распределение чётности по всем дискам  
   - **Преимущества:** баланс надёжности и эффективности ёмкости  
   - **Недостатки:** медленная запись, риск при восстановлении  
   - **Минимум:** 3 диска

4. **RAID 6** — двойная чётность  
   - **Преимущества:** выдерживает отказ двух дисков  
   - **Недостатки:** ещё более медленная запись  
   - **Минимум:** 4 диска

5. **RAID 10 (1+0)** — зеркало из чередующихся массивов  
   - **Преимущества:** высокая производительность + надёжность  
   - **Недостатки:** высокая стоимость  
   - **Минимум:** 4 диска

### **Программный RAID (mdadm)**
В Linux RAID реализуется на программном уровне через **mdadm**. Это даёт гибкость и независимость от конкретного оборудования. Основные команды управления:
- Создание массива: `mdadm --create`
- Мониторинг: `cat /proc/mdstat`
- Управление дисками: добавление, удаление, замена

Конфигурация сохраняется в `/etc/mdadm/mdadm.conf` и должна быть обновлена после изменений.

## **3. LVM (Менеджер логических томов)**

**LVM** — система абстракции над физическими дисками, позволяющая гибко управлять пространством.

### **Основные компоненты LVM:**

1. **Физические тома (PV)** — физические диски или разделы
2. **Группы томов (VG)** — пулы из физических томов
3. **Логические тома (LV)** — аналоги разделов, создаваемые из VG

### **Преимущества LVM:**
- **Гибкость:** можно легко изменять размер томов
- **Объединение:** несколько физических дисков в один логический
- **Снимки (snapshots):** создание моментальных копий на лету
- **Миграция:** возможность переносить данные между дисками без остановки системы

### **Типы логических томов:**
- **Линейные:** обычные тома
- **Тонкие (thin provisioning):** выделение места по мере необходимости
- **Тонкие пулы (thin pools):** общее пространство для тонких томов
- **Снимки (snapshots):** копии томов на определённый момент времени

### **Критические операции:**
- **Расширение тома:** можно выполнять на лету для большинства ФС
- **Уменьшение тома:** опасная операция, требует предварительного сжатия ФС
- **Миграция данных (pvmove):** перемещение данных между физическими дисками

---

## **4. Комбинирование RAID и LVM**

На практике часто используется комбинация **RAID + LVM**:
1. **RAID обеспечивает** отказоустойчивость на аппаратном уровне
2. **LVM предоставляет** гибкость управления пространством

**Рекомендуемая архитектура:**  
Физические диски → RAID массив → LVM физический том → Группа томов → Логические тома

Такой подход объединяет надёжность RAID с гибкостью LVM.

## **5. Восстановление данных**

### **Причины потери данных:**
- Логические: случайное удаление, форматирование, повреждение ФС
- Физические: выход дисков из строя
- Программные: ошибки ПО, вирусы

### **Этапы восстановления:**
1. **Оценка повреждений** — определение типа проблемы
2. **Создание образа** — работа с копией диска (dd, ddrescue)
3. **Восстановление структуры** — разделов, ФС
4. **Извлечение данных** — файлов

### **Методы восстановления:**
- **По метаданным ФС** — для недавно удалённых файлов в Ext3/4, XFS
- **По сигнатурам файлов (carving)** — поиск по заголовкам файлов (Photorec)
- **Восстановление структуры** — разделов (TestDisk), RAID массивов

### **Критические моменты:**
- **Не монтировать повреждённый диск в режиме записи**
- **Сначала создать образ, затем работать с ним**
- **Использовать надёжные инструменты:** TestDisk, Photorec, extundelete

## **6. Рекомендации по организации хранения**

1. **Разделение по назначению:**
   - `/` (корневая) — системные файлы
   - `/home` — пользовательские данные
   - `/var` — изменяемые данные (логи, кэши)
   - `/tmp` — временные файлы

2. **Выбор RAID уровня:**
   - Для ОС и приложений — RAID 1
   - Для пользовательских данных — RAID 5/6
   - Для высоконагруженных БД — RAID 10

3. **Мониторинг:**
   - Регулярная проверка SMART-статуса дисков
   - Мониторинг состояния RAID массивов
   - Контроль свободного места

4. **Резервное копирование:**
   - LVM snapshots для быстрых бэкапов
   - Регулярное архивирование на отдельные носители
   - Проверка целостности бэкапов

### **Типичные ошибки:**
- Использование LVM без RAID для критичных данных
- Отсутствие мониторинга состояния дисков
- Неправильный выбор размера ФС при создании
- Отсутствие плана восстановления

## **7. Современные тенденции**

1. **Переход к Btrfs и ZFS** — файловые системы со встроенными возможностями RAID и LVM
2. **Программно-определяемое хранилище (SDS)** — абстракция от физического железа
3. **Контейнеризация** — управление хранилищем через оркестраторы (Kubernetes CSI)
4. **NVMe и SSD** — новые протоколы и типы носителей

**Заключение:** Управление дисками в Linux — критически важный навык для системного администратора. Понимание принципов RAID и LVM позволяет строить отказоустойчивые и гибкие системы хранения, а знание методов восстановления данных помогает минимизировать потери при сбоях. Ключ к успеху — продуманная архитектура, регулярный мониторинг и наличие проверенных процедур восстановления.
