## **1. Netfilter — фреймворк ядра Linux**

**Netfilter** — это встроенный в ядро Linux **фреймворк**, предоставляющий набор **хуков** (hook points) в сетевом стеке ядра для обработки сетевых пакетов. Это не пользовательская программа, а инфраструктура внутри ядра.

*   **Место действия:** Работает на **сетевом (L3) и транспортном (L4) уровнях** модели OSI.
*   **Принцип:** Позволяет регистрировать обработчики (модули) на определенных этапах пути пакета через систему. Эти обработчики могут:
    *   Фильтровать пакеты (принимать/отбрасывать).
    *   Модифицировать пакеты (изменять адреса, порты — NAT/Masquerading).
    *   Помечать пакеты (для сложной маршрутизации).
*   **Архитектура:** Пакет проходит через цепочки (chains) хуков ядра: **PREROUTING**, **INPUT**, **FORWARD**, **OUTPUT**, **POSTROUTING**.

## **2. iptables — пользовательская утилита управления Netfilter**

**iptables** — это **командная утилита** (интерфейс), которая позволяет администратору настраивать таблицы правил, обрабатываемые фреймворком Netfilter. Это основной инструмент для настройки фаервола, трансляции адресов (NAT) и управления пакетами в Linux.

*   **Роль:** Переводчик с человеческого языка на язык ядра. Когда вы выполняете команду `iptables`, она преобразует ваши правила в набор структур данных, которые загружаются в ядро и обрабатываются Netfilter.

### **Базовая архитектура iptables:**
В Netfilter существует несколько **таблиц (tables)**, каждая для своих целей. Внутри таблиц — **цепочки (chains)**. Внутри цепочек — **правила (rules)**.

**Основные таблицы:**
1.  **`filter`** (по умолчанию) — для фильтрации пакетов (фаервол).
2.  **`nat`** — для трансляции сетевых адресов (NAT, PAT).
3.  **`mangle`** — для специального изменения пакетов (изменение TTL, маркировка пакетов).
4.  **`raw`** — для настройки исключений из connection tracking (чтобы не отслеживать определенные соединения).
5.  **`security`** — для правил Mandatory Access Control (используется SELinux).

**Стандартные цепочки (chains) в таблице `filter`:**
*   **INPUT** — для пакетов, **адресованных самой этой системе**.
*   **FORWARD** — для пакетов, которые система должна **проксировать/перенаправить** (если она работает как маршрутизатор).
*   **OUTPUT** — для пакетов, **исходящих от самой этой системы**.

**Стандартные цепочки в таблице `nat`:**
*   **PREROUTING** — изменение пакетов **перед** маршрутизацией (обычно для DNAT — изменение адреса назначения).
*   **POSTROUTING** — изменение пакетов **после** маршрутизации (обычно для SNAT/Masquerade — изменение адреса источника).
*   **OUTPUT** — для NAT на локально генерируемых пакетах.

## **3. Структура правил iptables**

Каждое правило состоит из **селектора (условия)** и **цели (действия)**.

**Общий синтаксис команды:**
```bash
iptables [-t таблица] команда цепочка [параметры селектора] -j цель
```
*   `-t таблица` — если не указано, используется `filter`.
*   `команда` — что делать с правилом ( `-A` добавить, `-D` удалить, `-I` вставить, `-L` вывести список, `-F` очистить и т.д.).
*   `цепочка` — `INPUT`, `OUTPUT`, `FORWARD` и др.
*   `селекторы` — условия для сопоставления пакета.
*   `-j цель` — что сделать с пакетом, если он совпал с условиями.

### **Основные цели (actions):**
*   **`ACCEPT`** — принять пакет.
*   **`DROP`** — бесшумно отбросить (без отправки уведомления отправителю).
*   **`REJECT`** — отклонить с отправкой сообщения об ошибке (по умолчанию `icmp-port-unreachable`).
*   **`LOG`** — залогировать пакет в системный журнал (`/var/log/syslog`, `kern.log`) и продолжить обработку следующим правилом.
*   **`SNAT`**, **`DNAT`**, **`MASQUERADE`** — цели для таблицы `nat`.
*   **`RETURN`** — вернуться из пользовательской цепочки в вызывающую.

### **Основные селекторы (условия):**
*   **Протокол и адреса:**
    *   `-p tcp|udp|icmp|...` — протокол.
    *   `-s IP_адрес/маска` — адрес источника.
    *   `-d IP_адрес/маска` — адрес назначения.
*   **Интерфейсы:**
    *   `-i имя_интерфейса` — входящий интерфейс (для цепочек `INPUT`, `FORWARD`, `PREROUTING`).
    *   `-o имя_интерфейса` — исходящий интерфейс (для цепочек `OUTPUT`, `FORWARD`, `POSTROUTING`).
*   **Порты (для `-p tcp/udp`):**
    *   `--sport порт` — порт источника.
    *   `--dport порт` — порт назначения.
*   **Состояние соединения (очень важно!):**
    *   `-m state --state состояние` — проверка состояния (устаревшая форма).
    *   `-m conntrack --ctstate состояние` — современная форма.
    *   **Состояния:** `NEW` (новое соединение), `ESTABLISHED` (установленное), `RELATED` (связанное, например, FTP data), `INVALID` (некорректное).

## **4. Практические примеры правил**

### **Пример 1: Базовая политика безопасности (default deny)**
```bash
# Очистить все правила и установить политики по умолчанию DROP
iptables -F            # Очистить все цепочки (flush)
iptables -X            # Удалить все пользовательские цепочки
iptables -Z            # Обнулить счетчики пакетов

# Установить политику по умолчанию DROP для всех цепочек
iptables -P INPUT DROP
iptables -P FORWARD DROP
iptables -P OUTPUT DROP

# Разрешить loopback-интерфейс (обязательно!)
iptables -A INPUT -i lo -j ACCEPT
iptables -A OUTPUT -o lo -j ACCEPT

# Разрешить уже установленные и связанные соединения (чтобы работали ответы)
iptables -A INPUT -m conntrack --ctstate ESTABLISHED,RELATED -j ACCEPT
iptables -A OUTPUT -m conntrack --ctstate ESTABLISHED,RELATED -j ACCEPT
```
Теперь система изолирована. Нужно добавлять правила для разрешения нужного трафика.

### **Пример 2: Разрешить SSH (порт 22) и веб-сервер (порт 80, 443)**
```bash
# Разрешить входящий SSH (TCP порт 22)
iptables -A INPUT -p tcp --dport 22 -j ACCEPT

# Разрешить входящий HTTP/HTTPS
iptables -A INPUT -p tcp --dport 80 -j ACCEPT
iptables -A INPUT -p tcp --dport 443 -j ACCEPT

# Разрешить исходящий DNS-запросы (UDP порт 53)
iptables -A OUTPUT -p udp --dport 53 -j ACCEPT

# Разрешить исходящие HTTP/HTTPS-соединения (чтобы система могла обновляться)
iptables -A OUTPUT -p tcp --dport 80 -j ACCEPT
iptables -A OUTPUT -p tcp --dport 443 -j ACCEPT
```

### **Пример 3: NAT и перенаправление портов (порт 2222 → 22 на внутреннем хосте)**
```bash
# Включить форвардинг пакетов в ядре (sysctl net.ipv4.ip_forward=1)

# Разрешить форвардинг для нашего трафика
iptables -A FORWARD -i eth0 -o eth1 -m conntrack --ctstate NEW,ESTABLISHED,RELATED -j ACCEPT
iptables -A FORWARD -i eth1 -o eth0 -m conntrack --ctstate ESTABLISHED,RELATED -j ACCEPT

# Маскарадинг (SNAT) для выхода в интернет с внутренней сети 192.168.1.0/24
iptables -t nat -A POSTROUTING -s 192.168.1.0/24 -o eth0 -j MASQUERADE

# Перенаправление (DNAT) входящего порта 2222 на внешнем интерфейсе на порт 22 внутреннего хоста 192.168.1.100
iptables -t nat -A PREROUTING -p tcp -i eth0 --dport 2222 -j DNAT --to-destination 192.168.1.100:22
iptables -A FORWARD -p tcp -d 192.168.1.100 --dport 22 -j ACCEPT
```

### **Пример 4: Защита от SYN-flood атаки**
```bash
# Ограничить количество новых TCP-соединений (SYN-пакетов) до 10 в секунду с одного IP
iptables -A INPUT -p tcp --syn -m limit --limit 10/s --limit-burst 20 -j ACCEPT
iptables -A INPUT -p tcp --syn -j DROP  # Все остальные SYN-пакеты отбрасываем
```

## **5. Важные замечания и best practices**

1.  **Порядок правил имеет значение!** iptables проверяет правила последовательно, от первого к последнему. Первое совпавшее правило определяет судьбу пакета.
2.  **Сохраняйте правила!** Правила, заданные через `iptables`, сбрасываются после перезагрузки. Для сохранения:
    *   **Debian/Ubuntu:** `iptables-save > /etc/iptables/rules.v4`
    *   **RHEL/CentOS/Fedora:** Используйте службу `iptables` или `firewalld`.
    *   Или установите пакет `iptables-persistent` (Debian).
3.  **Используйте модуль `conntrack`:** Это основа Stateful Packet Inspection (SPI). Позволяет легко разрешать ответы на установленные соединения.
4.  **Будьте осторожны с правилами `OUTPUT`:** Часто в цепочке `OUTPUT` оставляют политику `ACCEPT`, чтобы не ломать работу системы, а фильтруют только входящий (`INPUT`) трафик.
5.  **Логируйте подозрительную активность:**
    ```bash
    iptables -A INPUT -p tcp --dport 22 -m limit --limit 3/min --limit-burst 3 -j LOG --log-prefix "SSH attack: "
    iptables -A INPUT -p tcp --dport 22 -j DROP
    ```
6.  **Не блокируйте себя!** При настройке удаленно (по SSH) всегда добавляйте правило разрешения SSH **перед** сменой политики на `DROP` или используйте `fail2ban` с умом.

## **6. Эволюция: nftables**

**nftables** — это современная замена iptables, появившаяся в ядре Linux 3.13. Она использует тот же фреймворк Netfilter, но предоставляет:
*   **Единый синтаксис** для всех протоколов (IPv4, IPv6, ARP, bridge).
*   **Упрощённую архитектуру** (меньше цепочек и таблиц по умолчанию).
*   **Более производительный механизм** правил.
*   **Улучшенный синтаксис** правил (похож на язык программирования).

**Пример аналогичного правила nftables:**
```bash
nft add rule inet filter input tcp dport 22 accept
```

**Рекомендация:** Для новых систем изучайте и используйте **nftables**. iptables остаётся для совместимости, и его знание обязательно из-за распространённости существующих конфигураций.

---

**Итог:** **iptables** — это мощный и фундаментальный инструмент для контроля сетевого трафика в Linux, основанный на фреймворке **Netfilter**. Его необходимо знать любому системному администратору или специалисту по безопасности Linux-систем для настройки базового фаервола, NAT и простой защиты от сетевых атак.
