**lifetimes** — это механизм, который гарантирует, что **ссылки не станут висячими**.
### 1. Основная идея lifetimes

Ссылка (`&T` или `&mut T`) **не может жить дольше того значения, на которое она ссылается**.

Простейший пример:

```rust
let r;
{
    let s = String::from("hello");
    r = &s; // ошибка
} // s выходит из scope, r теперь dangling
```

Компилятор выдаст ошибку: ссылка `r` не может жить дольше `s`.

**Идея lifetimes:** каждому значению и каждой ссылке компилятор приписывает «время жизни». Он проверяет, что ссылку нельзя использовать после того, как её владелец уничтожен.

---

### 2. Компилятор и elision

Для большинства простых случаев Rust **не требует явного указания lifetimes**. Это называется **lifetime elision**.

Примеры, которые компилируются без аннотаций:

```rust
fn print(s: &String) {
    println!("{}", s);
}
```

Компилятор автоматически понимает, что ссылка `s` живёт не дольше вызова функции.

---

### 3. Когда нужны явные lifetimes

Явные lifetimes нужны, когда компилятор **не может вывести взаимосвязь между временем жизни параметров и возвращаемым значением**.

Пример:

```rust
fn longest(s1: &String, s2: &String) -> &String {
    if s1.len() > s2.len() { s1 } else { s2 }
}
```

Компилятор выдаст ошибку: он не знает, как связать lifetimes двух входных ссылок с возвращаемой.

Решение — явно указать lifetime параметр:

```rust
fn longest<'a>(s1: &'a String, s2: &'a String) -> &'a String {
    if s1.len() > s2.len() { s1 } else { s2 }
}
```

Здесь `'a` означает:  
– обе входные ссылки живут как минимум `'a`,  
– возвращаемая ссылка тоже живёт не дольше `'a`.

---

### 4. Основные правила lifetimes

1. **Ссылка не может жить дольше своего владельца**.
2. **Компилятор требует явно только сложные случаи** (несколько параметров с разными lifetimes).
3. **Функции с одной ссылкой на вход** обычно не требуют аннотаций: Rust сам выводит lifetime.
    

Пример:

```rust
fn first_word(s: &String) -> &str {
    let bytes = s.as_bytes();
    // ...
    &s[0..5] // компилятор понимает lifetime автоматически
}
```

---

### 5. Lifetime аннотации в структурах

Если структура хранит ссылку, нужно явно указать lifetime:

```rust
struct Book<'a> {
    title: &'a str,
}

let name = String::from("Rust Book");
let b = Book { title: &name }; // ok
```

Без `'a` Rust не сможет гарантировать, что `Book` не будет жить дольше строки `name`.

---

### 6. Ключевая мысль

Lifetimes — это способ **связать жизненный цикл ссылок с жизненным циклом владельцев**, чтобы компилятор мог гарантировать безопасность памяти.

– Они предотвращают **dangling references**,  
– Не добавляют runtime overhead,  
– Часто могут быть **выведены компилятором**, но иногда требуют явного указания.
