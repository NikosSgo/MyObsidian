# Apache Kafka и RabbitMQ

## Apache Kafka

### Определение

**Kafka** — распределённая платформа для потоковой обработки событий (event streaming) с высокой пропускной способностью.

### Ключевые концепции

- **Topic** — именованный канал сообщений
- **Partition** — упорядоченная неизменяемая последовательность записей в топике
- **Broker** — сервер Kafka, хранящий partitions
- **Producer** — отправитель сообщений в топик
- **Consumer** — получатель сообщений из топика
- **Consumer Group** — группа потребителей, each partition читается только одним потребителем в группе

### Особенности

- Хранение событий (append-only log) с настраиваемым retention
- Высокая пропускная способность (100K+ msg/sec)
- Гарантия порядка внутри partition
- Exactly-once семантика (с версии 0.11)

## RabbitMQ

### Определение

**RabbitMQ** — брокер сообщений, реализующий протокол AMQP (Advanced Message Queuing Protocol).

### Ключевые концепции

- **Exchange** — маршрутизирует сообщения в очереди
- **Queue** — буфер сообщений для потребителей
- **Binding** — связь между exchange и queue
- **Routing Key** — ключ для маршрутизации

### Типы Exchange

| Тип | Маршрутизация |
|-----|---------------|
| **Direct** | По точному совпадению routing key |
| **Fanout** | Рассылка во все привязанные очереди |
| **Topic** | По шаблону (`.log.error`) |
| **Headers** | По заголовкам сообщения |

## Сравнение

| Критерий | Kafka | RabbitMQ |
|----------|-------|----------|
| Модель | Distributed log (event streaming) | Message broker (очереди) |
| Пропускная способность | Очень высокая | Средняя |
| Латентность | Средняя (ms) | Низкая (μs–ms) |
| Порядок сообщений | Гарантирован в partition | Не гарантирован (default) |
| Персистентность | Долгосрочная (дни–месяцы) | До обработки��费者 |
| Повторная обработка | Да (offset) | Да (manual ack) |
| Протокол | Собственный | AMQP, MQTT, STOMP |

## Когда что выбирать

- **Kafka:** логирование, аналитика в реальном времени, event sourcing, high-throughput pipelines
- **RabbitMQ:** микросервисная маршрутизация, task queues, RPC, когда нужна низкая латентность
