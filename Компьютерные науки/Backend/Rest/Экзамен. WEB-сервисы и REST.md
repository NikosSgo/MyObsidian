### WEB-сервисы

**WEB-сервис** — программная система, доступная через веб по стандартным протоколам (HTTP/HTTPS). Предоставляет API для взаимодействия между приложениями.

**Архитектура WEB-сервисов:**

1. **SOAP (Simple Object Access Protocol)** — XML-based протокол. Использует WSDL (Web Services Description Language).
   - Строгая типизация, стандартизация
   - Тяжёлый, сложный
   - Применение: корпоративные системы, банкинг

2. **REST (Representational State Transfer)** — архитектурный стиль, основанный на HTTP.
   - Лёгкий, использует JSON/XML
   - Масштабируемый, кешируемый
   - Доминирует в современных веб-API

---

### REST — требования

1. **Client-Server** — разделение клиента и сервера
2. **Stateless** — каждый запрос содержит всю нужную информацию (нет состояния на сервере)
3. **Cacheable** — ответы кешируются
4. **Uniform Interface** — единый интерфейс (ресурсы, HTTP-методы, статусы)
5. **Layered System** — возможность прокси, балансировщиков
6. **Code on Demand** (опционально) — сервер может расширять клиента скриптами

**RESTful API — принципы:**
- Всё — ресурс (URL: `/users`, `/users/123`)
- Действия через HTTP методы: `GET` (читать), `POST` (создать), `PUT/PATCH` (обновить), `DELETE` (удалить)
- Статус-коды: `200 OK`, `201 Created`, `204 No Content`, `400 Bad Request`, `404 Not Found`, `500 Internal Server Error`
- Идемпотентность: GET, PUT, DELETE — идемпотентны; POST — нет

**Пример REST API:**
```
GET    /api/users          → список пользователей
GET    /api/users/42       → пользователь #42
POST   /api/users          → создать пользователя
PUT    /api/users/42       → обновить пользователя
DELETE /api/users/42       → удалить пользователя
GET    /api/users/42/orders → заказы пользователя
```
