### Принципы SOLID

#### S — Single Responsibility (единственная ответственность)
**Класс должен иметь только одну причину для изменения.**
- ❌ Класс `Invoice`, который и считает сумму, и сохраняет в БД, и генерирует PDF
- ✅ Разделить на `InvoiceCalculator`, `InvoiceRepository`, `InvoicePDFGenerator`

#### O — Open/Closed (открытость/закрытость)
**Классы открыты для расширения, закрыты для изменения.**
- ❌ Менять существующий код при добавлении новой функциональности
- ✅ Использовать наследование, композицию, полиморфизм
```python
# Вместо if-elif для новых типов:
class Discount:
    def apply(self, price): pass

class StudentDiscount(Discount):
    def apply(self, price): return price * 0.8
```

#### L — Liskov Substitution (подстановка Лисков)
**Объекты подкласса должны заменять объекты базового класса без нарушения логики.**
- ❌ Класс `Square` наследует `Rectangle`, но меняет поведение (setWidth задаёт и высоту)
- ✅ Лучше общий класс `Shape` и отдельно `Rectangle`, `Square`

#### I — Interface Segregation (разделение интерфейсов)
**Много специализированных интерфейсов лучше, чем один «толстый».**
- ❌ Один интерфейс `Worker` с методами `work()`, `eat()`, `sleep()` — робот не ест
- ✅ Разделить на `Workable`, `Eatable`, `Sleeper`

#### D — Dependency Inversion (инверсия зависимостей)
**Модули верхних уровней не зависят от нижних; оба зависят от абстракций.**
- ❌ `ReportService` создаёт `MySQLRepository` напрямую
- ✅ `ReportService` зависит от абстракции `Repository`, реализация подставляется извне (DI)
```python
class ReportService:
    def __init__(self, repo: Repository):  # инверсия
        self.repo = repo
```

**Зачем SOLID:** снижение связанности (coupling), повышение переиспользуемости, лёгкость тестирования и сопровождения.
