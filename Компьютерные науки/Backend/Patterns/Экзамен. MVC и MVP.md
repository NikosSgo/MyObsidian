### Архитектурный паттерн MVC

**MVC (Model-View-Controller)** — разделение приложения на 3 компонента:

| Компонент | Обязанности |
|---|---|
| **Model** | Данные, бизнес-логика, работа с БД. Не знает о View/Controller. |
| **View** | Отображение данных (UI). Реагирует на изменения Model. |
| **Controller** | Обрабатывает ввод пользователя, изменяет Model и/или View. |

**Поток** (для CRUD операции «Создать пользователя»):
```
User → Controller.createUser(data)
Controller → Model.create(data)   # сохраняем
Model → View.update(users)        # обновляем отображение
View → User: отображает список
```

### MVC vs MVP

| Аспект | MVC | MVP |
|---|---|---|
| Связь View-Model | View подписан на Model (Observer) | View через Presenter |
| Тестируемость | View сложно тестировать | Presenter тестируется без UI |
| Толщина | Controller тонкий | Presenter толстый |
| Когда | Веб-приложения (Django, Rails) | Сложные GUI (Windows Forms, Android) |

В **MVP** Presenter управляет View: View делегирует все действия Presenter'у, Presenter изменяет Model и обновляет View.

### Стереотипы в UML для MVC

Стереотип — расширение стандартного элемента UML, обозначается в `<<>>`.

**Для MVC используются стереотипы:**
- `<<controller>>` — класс-контроллер
- `<<view>>` — класс-представление
- `<<model>>` — класс-модель

```
┌─────────────────┐       ┌─────────────────┐
│  <<controller>>  │──────>│   <<model>>     │
│  UserController  │       │   User          │
└────────┬─────────┘       └─────────────────┘
         │
         │
         ▼
┌─────────────────┐
│   <<view>>      │
│   UserView      │
└─────────────────┘
```

### Реализации MVC

**1. MVC «толстая модель» (Classic MVC):**
- Model: бизнес-логика + данные
- View: подписан на Model (Observer)
- Controller: тонкий, только перенаправляет
- *Пример:* Smalltalk-80, Django (MTV — Model-Template-View)

**2. MVC «толстый контроллер» (Web MVC):**
- View: шаблон без логики
- Controller: вся логика, обновляет Model и выбирает View
- *Пример:* Spring MVC, ASP.NET MVC

**Когда использовать:**
- Classic MVC: для десктопных приложений с богатым UI
- Web MVC: для веб-приложений (запрос-ответ)

**Общее:** разделение ответственности, переиспользование Model, независимость View.
