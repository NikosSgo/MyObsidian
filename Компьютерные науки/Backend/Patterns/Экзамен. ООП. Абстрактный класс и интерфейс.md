### Основные концепции ООП

1. **Абстракция** — выделение существенных характеристик объекта, скрытие деталей реализации.
2. **Инкапсуляция** — сокрытие внутреннего состояния и обязательное взаимодействие через публичные методы.
3. **Наследование** — класс может наследовать свойства и методы другого класса (IS-A отношение).
4. **Полиморфизм** — единый интерфейс для разных типов данных (переопределение методов, перегрузка).

---

### Сравнение ООП-языков

| Характеристика | Python | Java | C++ | C# |
|---|---|---|---|---|
| Множественное наследование | Да | Нет (интерфейсы) | Да | Нет (интерфейсы) |
| Интерфейсы | Неформальные (ABC) | `interface` | Чистые виртуальные | `interface` |
| Инкапсуляция | `_`, `__` (соглашение) | `private, protected` | `private, protected` | `private, protected` |
| Статическая типизация | Нет | Да | Да | Да |
| Перегрузка методов | Нет (через *args) | Да | Да | Да |

### Абстрактный базовый класс vs Интерфейс

**Абстрактный класс:**
- Может содержать реализацию методов
- Может содержать поля и конструктор
- Наследуется (IS-A)
- *Пример:* `Shape` с методом `area()` — абстрактный, `display()` — реализован

```python
from abc import ABC, abstractmethod

class Shape(ABC):
    @abstractmethod
    def area(self): pass
    
    def display(self):           # общая реализация
        print(f"Area: {self.area()}")
```

**Интерфейс:**
- Только контракт (сигнатуры методов)
- Нет реализации, нет полей (в Java 8+ могут быть default-методы)
- Реализуется (IS-A capability)
- *Пример:* `Drawable` с методом `draw()`

```python
class Drawable(ABC):    # Python — через ABC
    @abstractmethod
    def draw(self): pass
```

**Когда что использовать:**
- **Абстрактный класс:** общая реализация для родственных классов (связь IS-A, есть общее состояние)
- **Интерфейс:** контракт для классов разной природы (способность делать что-то, нет общего состояния)

**Множественное наследование** (Python, C++) — класс может наследовать несколько базовых классов, что может привести к ромбовидной проблеме (Diamond Problem). В Java/C# — только множественная реализация интерфейсов.
