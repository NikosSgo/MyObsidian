# Экзамен. Пакеты Java и модификаторы доступа

## Пакеты в Java

Пакет — логическая группировка классов, аналог папок в файловой системе.

```java
package com.example.myapp.services;

import java.util.List;           // импорт конкретного класса
import java.util.*;              // импорт всех классов пакета
import com.example.myapp.model.User;  // импорт из другого пакета
```

- Каждый файл — **один** `package` (первая строка)
- `package` + `import` — механизм организации и управления доступом

## Модификаторы доступа

| Модификатор | Класс | Пакет | Подкласс | Везде |
|-------------|-------|-------|----------|-------|
| `public` | ✓ | ✓ | ✓ | ✓ |
| `protected` | ✓ | ✓ | ✓ | ✗ |
| *(default)* | ✓ | ✓ | ✗ | ✗ |
| `private` | ✓ | ✗ | ✗ | ✗ |

### public
Доступен отовсюду. Пример: `public class UserService {}`

### protected
Доступен в пакете + в подклассах (даже в других пакетах).
```java
class Animal {
    protected void breathe() {}
}
class Dog extends Animal {
    void bark() { breathe(); } // ✓ подкласс другого пакета
}
```

### default (package-private)
Без модификатора. Доступен только в пределах **одного пакета**.
```java
class Helper {    // нет модификатора = default
    void doWork() {} // доступен только в com.example.myapp
}
```

### private
Доступен только внутри **самого класса**. Инкапсуляция.
```java
class BankAccount {
    private double balance;
    public double getBalance() { return balance; }
}
```

## Ключевые правила

- Вложенные/внутренние классы могут быть `private`, `protected` или `default`
- Вне класса: только `public` и `default` (на уровне файла)
- Интерфейсы: методы по умолчанию `public`, поля — `public static final`
- `final` + `private` — константы, недоступные наследникам
