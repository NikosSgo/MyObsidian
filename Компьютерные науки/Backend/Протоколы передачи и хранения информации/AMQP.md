**Advanced Message Queue Protocol** - открытый бинарный протокол прикладного уровня для передачи сообщений между программами, обеспечивающий надёжную асинхронную доставку сообщений.

## Ключевая модель
- **Брокер сообщений** - программа, которая получает сообщения от отправителя и передаёт их получателю
- **Обменники** - получает сообщения от отправителей и по правилам отправляют их в очереди. У них есть 4 типа
	1) Direct - есть ключ полностью совпадает
	2) Fanout - игнорирует ключ
	3) Topic - использует маски для сопоставления, ключи разделяются точкой, а символ заменяет одно слово, а # - ноль и более 
	4) Headers - игнорирует ключи и смотри на заголовки сообщения
- **Очередь** - хранит сообщения до тех пор, пока consumer их не заберёт и не подтвердит обработку
- **Привязка** - правило, которое связывает обменники и очереди по ключу маршрутизации

## AMQP сообщения и фреймы

Сообщения в протоколе отправляются фреймами и он содержит:

**Типы фреймов**:
*   **`method`**- содержит команду, например, `basic.publish`.
*   **`header`**- содержит метаданные сообщения (заголовки, Content-Type, Delivery Mode и т.д.).
*   **`body`**- содержит само тело (payload) сообщения. Одно сообщение может быть разбито на несколько body-фреймов.
*   **`heartbeat`**- используется для проверки, что соединение живо.


### Общая структура фрейма выглядит так:

| Размер (байт)  | 1              | 2                   | 4                 | Переменный                      | 1                       |
| :------------- | :------------- | :------------------ | :---------------- | :------------------------------ | :---------------------- |
| **Содержимое** | **Тип (type)** | **Канал (channel)** | **Размер (size)** | **Полезная нагрузка (payload)** | **Маркер конца (0xCE)** |
### Разбор последовательности фреймов для отправки сообщения

Процесс отправки одного сообщения (например, через `basic.publish`) выглядит как последовательность из трех фреймов:

**1. Фрейм-метод (Method Frame)**
Содержит информацию о том, какое действие нужно выполнить.
```text
┌──────────────┬───────────────┬──────────────────────────┐
│  class_id    │  method_id    │  arguments               │
│  (2 байта)   │  (2 байта)    │  (переменный размер)     │
├──────────────┼───────────────┼──────────────────────────┤
│  40 (basic)  │  10 (publish) │  exchange, routing_key   │
└──────────────┴───────────────┴──────────────────────────┘
```

**2. Фрейм-заголовок (Header Frame)**
Содержит метаданные о сообщении: размер тела, флаги и свойства (content-type, delivery-mode и т.д.).
```text
┌──────────────┬──────────┬──────────────┬──────────────────┬─────────────────┐
│  class_id    │  weight  │  body_size   │  property_flags  │  properties     │
│  (2 байта)   │ (2 байта)│   (8 байт)   │    (2 байта)     │ (перем. размер) │
├──────────────┼──────────┼──────────────┼──────────────────┼─────────────────┤
│  40 (basic)  │  0       │  размер JSON │   битовая маска  │  content-type,  │
│              │          │  (в байтах)  │   для свойств    │  delivery-mode  │
└──────────────┴──────────┴──────────────┴──────────────────┴─────────────────┘
```

**3. Фрейм(ы)-тело (Body Frame)**
Содержит полезную нагрузку, например, JSON-данные.
```text
┌──────────────────────────────┐
│      content (тело)          │
│   (переменный размер)        │
├──────────────────────────────┤
│   {"key": "value"}           │
└──────────────────────────────┘
```

### Методы AMQP (команды протокола)

Методы в AMQP — это не функции в коде, а **сетевые команды**, которые клиент и брокер отправляют друг другу в `method`-фреймах. Они сгруппированы по классам в зависимости от того, с какой сущностью работают:

*   **`connection`** — управление соединением: `start`, `tune`, `open`, `close`.
*   **`channel`** — управление виртуальными каналами внутри одного TCP-соединения: `open`, `flow`, `close`.
*   **`exchange`** — создание и удаление обменников: `declare`, `delete`, `bind`.
*   **`queue`** — создание, привязка и удаление очередей: `declare`, `bind`, `delete`, `purge`.
*   **`basic`** — публикация и потребление сообщений: `publish`, `consume`, `deliver`, `ack`, `reject`, `get`.

Большинство методов работают по принципу **"запрос-ответ"**: клиент отправляет команду (например, `queue.declare`), а брокер отвечает методом с суффиксом `-ok` (`queue.declare-ok`), подтверждая действие и возвращая результат. Исключение — `basic.publish`, который не ждёт ответа, чтобы не замедлять отправку, брокер асинхронно отправляет ack на каждое принятое сообщение, если не смог записать на диск придёт basic.nack
