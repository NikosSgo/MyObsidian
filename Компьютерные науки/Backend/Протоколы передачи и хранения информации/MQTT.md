**Message Queuing Telemetry Transport** - открытый легковесный бинарный протокол прикладного уровня для передачи сообщений между устройствами, обеспечивающий надёжную доставку в условиях нестабильных сетей и ограниченных ресурсов.

## Ключевая модель
- **Брокер сообщений** - программа, которая получает сообщения от издателей и передаёт их подписчикам
- **Издатель (Publisher)** - устройство, которое отправляет сообщения в брокер по определённой теме
- **Подписчик (Subscriber)** - устройство, которое получает сообщения из брокера по интересующим темам
- **Тема (Topic)** - строковый идентификатор, по которому маршрутизируются сообщения. Использует иерархию через слеш (`/`), например: `sensors/temperature/kitchen`
- **Подписка (Subscription)** - правило, связывающее подписчика с темой. Поддерживает маски: `+` (один уровень) и `#` (несколько уровней)

## MQTT сообщения и пакеты

Сообщения в протоколе передаются в виде **пакетов (packets)**. Базовый пакет состоит из:

**Типы управляющих пакетов**:
*   **`CONNECT`** - клиент подключается к брокеру.
*   **`CONNACK`** - брокер подтверждает подключение.
*   **`PUBLISH`** - издатель отправляет сообщение по теме.
*   **`PUBACK`** - подтверждение получения сообщения (QoS 1).
*   **`PUBREC`** / **`PUBREL`** / **`PUBCOMP`** - четырёхшаговое подтверждение (QoS 2).
*   **`SUBSCRIBE`** / **`SUBACK`** - подписка на тему и её подтверждение.
*   **`PINGREQ`** / **`PINGRESP`** - проверка живости соединения (keep-alive).
*   **`DISCONNECT`** - отключение клиента.

### Общая структура пакета выглядит так:

| Размер (байт) | 1-4 (переменный) | Переменный |
| :--- | :--- | :--- |
| **Содержимое** | **Фиксированный заголовок (Fixed Header)** | **Переменный заголовок (Variable Header)** | **Полезная нагрузка (Payload)** |
| **Назначение** | Тип пакета + Флаги + Длина остатка | Зависит от типа пакета (например, Topic Name) | Само сообщение (payload) |

### Разбор пакета PUBLISH (отправка сообщения)

Пакет `PUBLISH` — это сердце MQTT. Он выглядит так:

**1. Фиксированный заголовок**
```text
┌──────────────┬──────────────────────────────┐
│  Тип + Флаги │      Длина остатка           │
│  (1 байт)    │      (1-4 байта)             │
├──────────────┼──────────────────────────────┤
│  0x30 (PUB)  │      длина данных            │
└──────────────┴──────────────────────────────┘
```

**2. Переменный заголовок**
```text
┌──────────────────────────────┬─────────────────┐
│     Имя темы (Topic Name)    │   Идентификатор │
│     (2 байта длины + строка) │   пакета (2 б)  │
├──────────────────────────────┼─────────────────┤
│  "sensors/temperature/kitchen"│    0x0001       │
└──────────────────────────────┴─────────────────┘
```

**3. Полезная нагрузка (Payload)**
```text
┌──────────────────────────────┐
│      Полезная нагрузка       │
│   (переменный размер)        │
├──────────────────────────────┤
│   {"temp": 22.5, "hum": 60}  │
└──────────────────────────────┘
```

## Уровни качества обслуживания (QoS)

В MQTT есть три уровня надёжности доставки, встроенных прямо в протокол:

| QoS | Название | Как работает | Дубли? | Когда использовать |
| :--- | :--- | :--- | :--- | :--- |
| **0** | **At most once** | "Отправил и забыл". Сообщение доставляется не более одного раза. Подтверждений нет. | ❌ Нет | Данные с датчиков, где потеря не критична |
| **1** | **At least once** | Гарантированная доставка. Отправитель ждёт `PUBACK`. Если не пришёл — пересылает. | ✅ Да | Управление устройствами, где дубли допустимы |
| **2** | **Exactly once** | Максимальная надёжность. Четырёхэтапное рукопожатие (`PUBREC` → `PUBREL` → `PUBCOMP`). | ❌ Нет | Платёжные транзакции, критичные команды |

## Подписка и маршрутизация

В MQTT нет обменников и очередей, как в AMQP. Вместо этого используется **иерархическая маршрутизация по темам**:

| Тип подписки | Пример темы | Что получит |
| :--- | :--- | :--- |
| **Точное совпадение** | `sensors/temperature/kitchen` | Только сообщения в эту тему |
| **Одноуровневая маска (`+`)** | `sensors/+/kitchen` | `sensors/temperature/kitchen`, `sensors/humidity/kitchen` |
| **Многоуровневая маска (`#`)** | `sensors/#` | `sensors/temperature/kitchen`, `sensors/humidity/bathroom`, `sensors/motion/living_room` |

## Методы MQTT (команды протокола)

Команды в MQTT — это **управляющие пакеты**, которые клиент и брокер отправляют друг другу:

*   **`CONNECT`** / **`CONNACK`** — установка соединения и аутентификация (логин/пароль).
*   **`PUBLISH`** — отправка сообщения в тему.
*   **`PUBACK`** / **`PUBREC`** / **`PUBREL`** / **`PUBCOMP`** — подтверждения для QoS 1 и 2.
*   **`SUBSCRIBE`** / **`SUBACK`** — подписка на тему (с указанием QoS).
*   **`UNSUBSCRIBE`** / **`UNSUBACK`** — отписка от темы.
*   **`PINGREQ`** / **`PINGRESP`** — keep-alive (проверка, что клиент жив).
*   **`DISCONNECT`** — корректное отключение клиента.

В отличие от AMQP, где многие методы работают по принципу "запрос-ответ" (с суффиксом `-ok`), в MQTT всё строится вокруг **пакетов-команд** и их подтверждений. Исключение — QoS 0, где `PUBLISH` не требует никакого ответа.

## Специальные возможности MQTT

- **Last Will and Testament (LWT)**: "Завещание". Клиент при подключении оставляет сообщение, которое брокер отправит всем подписчикам, если клиент неожиданно отключится.
- **Retained Messages**: "Сохранённые сообщения". Брокер хранит последнее сообщение по теме и отправляет его новому подписчику сразу после подписки.
- **Clean Session**: Если `false`, брокер сохраняет подписки и пропущенные сообщения для клиента на время его отключения.
- **Keep Alive**: Интервал, в течение которого клиент обязан отправлять `PINGREQ`, иначе брокер разорвёт соединение.

## 🔄 MQTT vs AMQP (коротко)

| Характеристика        | **AMQP 0-9-1**                                 | **MQTT**                                          |
| :-------------------- | :--------------------------------------------- | :------------------------------------------------ |
| **Модель**            | Обменники + Очереди + Привязки                 | Только темы (Topics)                              |
| **Сложность**         | Высокая (бинарный протокол, много сущностей)   | Низкая (лёгкий, до 2 байт заголовка)              |
| **Маршрутизация**     | Гибкая (4 типа обменников)                     | Иерархические темы с масками (`+`, `#`)           |
| **Уровни надёжности** | Publisher Confirms, Transactions, Consumer ACK | Три уровня QoS (0, 1, 2)                          |
| **Сценарий**          | Серверные системы, микросервисы                | **IoT, датчики, умный дом, мобильные приложения** |
| **Типичный брокер**   | RabbitMQ, ActiveMQ                             | Mosquitto, EMQX, HiveMQ                           |
