**DoS (Denial of Service)** — атака, направленная на нарушение доступности сервиса для легитимных пользователей.
**DDoS (Distributed DoS)** — распределённая DoS-атака, выполняемая с большого количества узлов (ботнет).

---

## **1. Классификация DDoS-атак**

### **A. По уровню OSI:**

#### **1. Атаки на канальном и сетевом уровне (L3-L4) — Volume-based attacks**
*   **Цель:** Переполнить пропускную способность канала.
*   **Механизмы:**
    *   **UDP Flood:** Массовая отправка UDP-пакетов на случайные порты.
    *   **ICMP Flood (Smurf/Ping Flood):** Отправка ICMP Echo Request.
    *   **DNS Amplification:** Использование открытых DNS-резолверов для усиления трафика (небольшой запрос → огромный ответ).
    *   **NTP Amplification:** Аналогично, с использованием протокола NTP.
    *   **SYN Flood:** Отправка TCP SYN-пакетов без завершения handshake, исчерпание таблицы соединений.
*   **Объём:** Могут достигать **сотен Гбит/с и Тбит/с**.

#### **2. Атаки на транспортном уровне (L4) — Protocol attacks**
*   **Цель:** Исчерпать ресурсы сервера (CPU, память, таблицы соединений).
*   **Механизмы:**
    *   **SYN Flood** (также относится сюда).
    *   **ACK Flood.**
    *   **TCP Connection Flood:** Установление большого количества полных TCP-соединений.
    *   **Slowloris/ Slow HTTP:** Медленная отправка HTTP-заголовков, удержание соединений открытыми.
    *   **Ping of Death / Teardrop:** Отправка некорректных фрагментированных пакетов, вызывающих краш системы.

#### **3. Атаки на прикладном уровне (L7) — Application-layer attacks**
*   **Цель:** Перегрузить логику приложения (веб-сервер, базу данных, API).
*   **Механизмы:**
    *   **HTTP Flood:** Массовые HTTP-запросы (GET/POST) к тяжёлым страницам (поиск, генерация отчётов).
    *   **CC Attack (Challenge Collapsar):** Атака на динамический контент.
    *   **DNS Query Flood:** Атака на DNS-сервер.
    *   **Атаки на уязвимости приложения:** Эксплойты, вызывающие отказ в обслуживании (например, через уязвимость в кэшировании).
*   **Особенность:** Низкий объём трафика (десятки Мбит/с), но высокая эффективность, так как запросы выглядят как легитимные.

### **B. По вектору атаки:**
*   **Прямые:** Атака напрямую на цель.
*   **Отражённые (Reflected):** Атака через посредников (серверы с открытыми службами — DNS, NTP, SSDP).
*   **Усиленные (Amplified):** Отражённые атаки, где ответ значительно превышает запрос (коэффициент усиления до 5000x для некоторых протоколов).

## **2. Многоуровневая стратегия защиты (Defense-in-Depth)**

Защита должна быть распределена между **провайдером/оператором**, **периметром** и **самим приложением**.

### **Уровень 1: Оператор связи / Провайдер (Upstream Provider)**
*   **Фильтрация на уровне магистрали (BGP Flowspec, RTBH — Remote Triggered Black Hole):** Маршрутизация атакующего трафика в "чёрную дыру" до того, как он загрузит канал клиента.
*   **Очистка трафика (Scrubbing Centers):** Специализированные центры, которые фильтруют DDoS-трафик и направляют чистый трафик клиенту (часто как услуга — **DDoS Mitigation as a Service**).
*   **Anycast DNS:** Распределение DNS-запросов по множеству географически распределённых серверов для поглощения атак.

### **Уровень 2: Периметр сети (On-premise / Cloud Perimeter)**
*   **Специализированные аппаратные/облачные решения (DDoS Mitigation Appliances):**
    *   **Arbor Networks (NETSCOUT), Radware, FortiDDoS, F5 Silverline.**
    *   Обнаружение на основе поведенческого анализа (Baseline Learning) и сигнатур.
*   **Облачные WAF и CDN с защитой от DDoS:**
    *   **Cloudflare, AWS Shield (Advanced), Akamai Prolexic, Google Cloud Armor.**
    *   **Принцип:** Трафик идёт сначала через инфраструктуру провайдера, которая фильтрует атаки L3-L7.
    *   **Скрытие реального IP-адреса сервера** — ключевая функция.

### **Уровень 3: Оборудование и ОС (Network & Host Hardening)**

#### **Настройка сетевого оборудования:**
1.  **Rate Limiting (ограничение скорости):**
    ```bash
    # Пример на Cisco IOS
    access-list 110 permit icmp any any echo
    rate-limit input access-group 110 512000 8000 8000 conform-action transmit exceed-action drop
    ```
2.  **Отключение ненужных сервисов и ICMP-ответов.**
3.  **Настройка TCP Intercept (для SYN Flood).**

#### **Настройка серверов (Linux):**
1.  **Увеличение размеров очередей:**
    ```bash
    sysctl -w net.core.somaxconn=2048
    sysctl -w net.ipv4.tcp_max_syn_backlog=2048
    ```
2.  **Включение защиты от SYN Flood:**
    ```bash
    sysctl -w net.ipv4.tcp_syncookies=1
    sysctl -w net.ipv4.tcp_synack_retries=2
    sysctl -w net.ipv4.tcp_syn_retries=2
    ```
3.  **Ограничение количества соединений с одного IP (iptables/nftables):**
    ```bash
    # Ограничить 20 новых соединений в минуту с одного IP на порт 80
    iptables -A INPUT -p tcp --dport 80 -m state --state NEW -m recent --set
    iptables -A INPUT -p tcp --dport 80 -m state --state NEW -m recent --update --seconds 60 --hitcount 20 -j DROP
    ```
4.  **Rate limiting с помощью iptables:**
    ```bash
    # Ограничить ICMP (ping) до 1 пакета в секунду
    iptables -A INPUT -p icmp -m limit --limit 1/s --limit-burst 10 -j ACCEPT
    iptables -A INPUT -p icmp -j DROP
    ```

### **Уровень 4: Прикладной уровень (Application Hardening)**

#### **Для веб-серверов (Nginx/Apache):**
1.  **Nginx:**
    ```nginx
    http {
        limit_conn_zone $binary_remote_addr zone=addr:10m;
        limit_req_zone $binary_remote_addr zone=one:10m rate=10r/s;

        server {
            limit_conn addr 10; # не более 10 соединений с одного IP
            limit_req zone=one burst=20 nodelay; # ограничение запросов

            location / {
                # Задержка для медленных клиентов
                client_body_timeout 10s;
                client_header_timeout 10s;
            }
        }
    }
    ```
2.  **Apache:** Модули `mod_evasive`, `mod_security`, `mod_qos`.

#### **Использование обратных прокси и кэширования:**
*   **Varnish Cache:** Кэширование статики и динамики для снижения нагрузки на бэкенд.
*   **HAProxy:** С возможностями rate limiting и защиты L7.

#### **Защита от Slowloris:**
*   **Модули:** `mod_antiloris` (Apache), `mod_reqtimeout` (Apache 2.2.15+).
*   **Настройка таймаутов:** Уменьшение `client_body_timeout`, `client_header_timeout`.

### **Уровень 5: Архитектурные меры**
1.  **Горизонтальное масштабирование:** Автоскейлинг группы серверов (AWS Auto Scaling, Kubernetes HPA).
2.  **Геораспределение:** Размещение сервисов в нескольких дата-центрах.
3.  **Микросегментация и изоляция:** Критические сервисы в отдельном сегменте сети.
4.  **Резервирование каналов:** Несколько uplink от разных провайдеров.
5.  **Использование облачных провайдеров:** Облака имеют огромную избыточную пропускную способность.

## **3. Процесс реагирования на DDoS-атаку (Incident Response)**

1.  **Обнаружение (Detection):**
    *   Мониторинг сетевого трафика (MRTG, Cacti, Zabbix, графика в панели хостинга).
    *   Резкий рост трафика, 100% загрузка CPU на сетевом оборудовании.
    *   Системы обнаружения (IDS/IPS, Arbor Sightline, собственные скрипты).

2.  **Классификация (Classification):**
    *   Определить тип атаки (SYN flood, HTTP flood, DNS amplification).
    *   Анализ трафика (tcpdump, Wireshark, `netstat -an`).
    *   Использовать инструменты: `ss`, `netstat`, `iftop`, `nethogs`.

3.  **Смягчение (Mitigation):**
    *   **Активировать план реагирования.**
    *   Уведомить провайдера хостинга/связи.
    *   Включить облачную защиту (изменить DNS-записи на адрес scrubbing-центра).
    *   Применить фильтры на маршрутизаторах и фаерволе.

4.  **Восстановление (Recovery):**
    *   Постепенное отключение фильтров после окончания атаки.
    *   Мониторинг на предмет повторной атаки.
    *   Анализ логов для выявления источников.

5.  **Последующий анализ (Post-mortem):**
    *   Определить ущерб (простой, финансовые потери).
    *   Обновить планы реагирования.
    *   Усилить защиту в выявленных слабых местах.

## **4. Инструменты для тестирования и мониторинга**

### **Мониторинг:**
*   **Сетевой трафик:** `iftop`, `nload`, `vnstat`, `bmon`.
*   **Сетевые соединения:** `ss`, `netstat`, `conntrack-tools`.
*   **Системные ресурсы:** `htop`, `nmon`, `dstat`.
*   **Специализированные:** Nagios, Zabbix, Prometheus с Grafana.

### **Тестирование (Только на своих тестовых стендах!):**
*   **hping3:** `hping3 -S --flood -p 80 <target>` (SYN flood).
*   **slowhttptest:** `slowhttptest -c 1000 -H -g -o slowhttp -i 10 -r 200 -t GET -u http://target` (Slowloris).
*   **GoldenEye:** `python3 goldeneye.py http://target` (HTTP flood).
*   **LOIC (Low Orbit Ion Cannon):** Простой, но известный инструмент.

## **5. Современные тренды и сложности**

1.  **AI/ML в защите:** Системы учатся на паттернах нормального трафика и автоматически обнаруживают аномалии.
2.  **Атаки на IoT-устройства:** Мираи, BASHLITE — ботнеты из камер, роутеров для мощных атак.
3.  **Атаки с малой скоростью (Low-and-Slow):** Трудноотличимы от легитимного трафика.
4.  **Целевые атаки на приложение (L7):** Требуют глубокого анализа поведения пользователей.
5.  **Смешанные (гибридные) атаки:** Одновременная атака на несколько уровней.

**Итог:** Полная защита от DDoS невозможна, но можно **минимизировать риски и последствия** с помощью:
1.  **Многоуровневой защиты** (провайдер → периметр → хост → приложение).
2.  **Использования облачных сервисов защиты** (Cloudflare, AWS Shield) для скрытия инфраструктуры.
3.  **Архитектурной устойчивости** (масштабирование, избыточность).
4.  **Готового плана реагирования** и регулярных учений.
5.  **Постоянного мониторинга** и анализа угроз.

**Главное правило:** Не ждать начала атаки. Защиту необходимо проектировать и внедрять заранее.
