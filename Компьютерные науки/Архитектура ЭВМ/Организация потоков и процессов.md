# Организация потоков и процессов

## Процесс

**Процесс** — программа в�行ении;拥有 собственный адресное пространство, таблицу страниц, дескрипторы файлов, контекст ядра.

## Поток (thread)

**Поток** — наименьшая единица, планируемая ОС. Потоки одного процесса разделяют адресное пространство, но имеют собственный стек, регистры, счётчик команд.

## Состояния потока

```
Создан (New) → Готов (Ready) → Выполняется (Running)
                                    ↓         ↓
                               Ожидает    Завершён
                              (Waiting)  (Terminated)
                                    ↓
                                  Ready
```

- **Created** — поток создан, но ещё не запущен
- **Ready** — готов к выполнению, ждёт процессора
- **Running** — выполняется на CPU
- **Waiting** — блокирован (ввод/вывод, мьютекс)
- **Terminated** — завершён

## Сравнение потока и процесса

| Критерий | Процесс | Поток |
|----------|---------|-------|
| Адресное пространство | Собственное | Разделяемое |
| Создание | Тяжёлое | Лёгкое |
| Переключение | Медленное | Быстрое |
| Взаимодействие | IPC (каналы,共享 память) | Прямой доступ к общей памяти |
| Надёжность | Изоляция | Один поток может уронить другие |

## Модели многопоточности

### Many-to-One (много-к-одному)
Много потоков → один поток ОС. Блокировка одного блокирует все. Реализован в older Green Threads (Java до 1.2).

### One-to-One (один-к-одному)
Каждый поток приложения → поток ОС. Полная параллельность. Модель Windows, Linux (NPTL).

### Many-to-Many (много-к-многим)
M потоков → N потоков ОС (M ≥ N). Гибкость, сложна в реализации. Solaris (до 9 версии), IRIX.

## Преимущества многопоточности

- **Адаптивность** — потоки продолжают работу при блокировке другого
- **Ресурсsharing** — общая память без IPC
- **Экономия** — переключение потока дешевле, чем процесса
- **Масштабируемость** — эффективное использование многоядерных CPU

## Модель ветвления-соединения (Fork-Join)

```
主线程:  ═══════════╗  ╔══════════
                     ║  ║
Поток 1: ════════╗  ╠══╝
                  ╠══╝
Поток 2: ════════╝
```

При `#pragma omp parallel` или `pthread_create` — создаётся вилка; при завершении — слияние.
