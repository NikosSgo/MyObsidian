## Зачем нужно кодирование

Передатчик не может отправить биты «как есть»: среда передаёт только физический сигнал — напряжение в кабеле, свет в оптоволокне или радиоволну. Кодирование задаёт, **какой сигнал и в какой момент** означает последовательность битов.

Обычно обработка идёт так: `данные → логическое кодирование → (помехоустойчивое кодирование) → физическое кодирование → сигнал`. У приёмника — в обратном порядке.

### По каким критериям код лучше или хуже

Единственного лучшего кода нет: это компромисс.

| Критерий                     | Что означает                                                                                      |
| ---------------------------- | ------------------------------------------------------------------------------------------------- |
| Полоса частот                | Чем чаще и резче переходы, тем шире канал нужен.                                                  |
| Синхронизация                | Приёмник должен понимать границы битов; для этого ему нужны переходы в сигнале.                   |
| Постоянная составляющая (DC) | Долгое преобладание одного уровня создаёт смещение; трансформаторы и AC-связь его плохо передают. |
| Устойчивость к шуму          | Чем сильнее различаются состояния сигнала, тем меньше риск перепутать их.                         |
| Скорость и избыточность      | Дополнительные биты или переходы повышают надёжность, но уменьшают полезную скорость.             |
| Сложность                    | Более эффективный код обычно сложнее передавать и принимать.                                      |

### Синхронизация — ключевая проблема

У передатчика и приёмника нет идеально одинаковых часов. Приёмник восстанавливает такт из изменений сигнала и решает: «сейчас середина очередного бита, надо измерить уровень». Если переходов долго нет (например, много одинаковых битов в NRZ), его оценка такта постепенно смещается и биты начинают считываться не в тех границах — это **потеря синхронизации**.

- Код с гарантированным переходом в каждом бите (Manchester) синхронизируется легко, но требует большей полосы.
- Код без гарантированных переходов (NRZ, NRZI, MLT-3) экономнее по полосе, но нуждается в логическом кодировании, скремблировании или служебных последовательностях.

**Кодирование в сетях** в общем случае **трёхступенчатое**.
## 3 Ступень: Физическое кодирование
Представление информации в виде различных сигналов: электрических, аналоговых, оптических. 
### Цифровое кодирование
Служит для передачи цифровых данных по основополосным каналам связи.
Цифровое кодирование делят на **потенциальное и импульсное**.

#### Потенциальное кодирование
Для представления логических единиц и нулей используют только значение потенциала.

- **NRZ** - потенциальное кодирование без возврата к нулю. Нижний потенциал - 0, верхний - 1, переходы на границе такта.
	![[NRZ схема.excalidraw]]
		Плюсы: простая реализация, небольшое количество переходов, относительно небольшая требуемая полоса частот.
		Минусы: длинные последовательности нулей или единиц не создают переходов, возможна потеря синхронизации, присутствует постоянная составляющая сигнала.

- **NRZ**I - потенциальное кодирование без возврата к нулю с инвертированием при единице. На каждом такте мы смотрим на предыдущий и если был отрицательный, то кодируем просто по потенциалу, а если был положительный, то меняем на противоположный. Может и наоборот быть отрицательный потенциал инвертирующем, например в USB используется.
	![[NRZI схема.excalidraw]] 
		Плюсы: значение бита не зависит от абсолютной полярности сигнала, меньше переходов, чем в Manchester, простая реализация.
		Минусы: длинная последовательность битов, не вызывающих переход, приводит к потере синхронизации, обычно требуется bit stuffing, блочное кодирование или скремблирование.
- **RZ** - импульсный код с возвратом к нулю. 1 передаётся положительным коротким потенциала на такте, а 0 полностью отрицательным потенциалом на всём такте. Есть ещё полярный где при 0 мы уходим -v и потом на том же такте возвращаемся в 0.  
	![[RZ схема.excalidraw]]
		Плюсы: больше переходов, чем в NRZ, приёмнику проще поддерживать синхронизацию, соседние единицы передаются отдельными импульсами.
		Минусы: требуется более широкая полоса частот, в униполярном RZ длинная последовательность нулей не создаёт переходов, используется три уровня сигнала в полярном варианте: `+V`, `0`, `-V`.
- **MLT-3 Multi level transmit** - трёхуровневое линейное кодирование. 1 кодируется переход из одного уровня потенциала в другой по циклу, при этом с 0, то есть из +v попадаем сначала в 0, потом в -v, потом в 0 и потом опять в +V
	![[MLT-3 схема.excalidraw]]
		Плюсы: низкая максимальная частота сигнала, требуется меньшая полоса пропускания, хорошо подходит для передачи по витой паре.
		Минусы: длинная последовательность нулей не создаёт переходов, само по себе кодирование плохо поддерживает синхронизацию, обычно используется вместе с блочным кодированием и скремблированием.
- **Манчестер** - 1 кодируется сначала -v потом переходом в +v в одном такте, а 0 сначала +v потом -v. Нулевой уровень не используется
	![[Манчестерское кодирование схема.excalidraw]]
		Плюсы: гарантированный переход в каждом бите, хорошая самосинхронизация, нет длинных участков постоянного уровня, отсутствует постоянная составляющая сигнала.
		Минусы: большое количество переходов, требуется примерно вдвое большая полоса по сравнению с простыми вариантами NRZ, плохо подходит для высоких скоростей передачи.
#### Аналоговое кодирование

### Базовая идея

**Несущая** — быстрая синусоида фиксированной частоты, например около `2,4 ГГц` в Wi‑Fi. Сама по себе она не несёт данных. Передатчик изменяет её параметры по битам — это и есть **модуляция**.


**Полоса частот** — участок частот, который канал способен передать. Например, не «все радиоволны», а только диапазон около несущей. **Узкая полоса** = маленький доступный диапазон: сигнал нельзя менять слишком резко и часто, иначе его спектр выйдет за пределы канала и начнёт мешать соседним каналам. Поэтому в узкой полосе стараются передать больше бит одним символом (например, QAM), а не просто сильнее ускорять изменения сигнала.

**Огибающая** — плавный контур, показывающий амплитуду волны. **Постоянная огибающая** означает: амплитуда не меняется; меняются только частота или фаза. Такой сигнал можно усиливать дешёвым нелинейным усилителем без сильного искажения. У FSK и обычной PSK огибающая постоянна; у ASK и QAM — нет.

Аналоговое кодирование, или модуляция, используется для передачи данных через канал с ограниченной полосой частот.

Данные изменяют параметры несущего аналогового сигнала:
- амплитуду;
- частоту;
- фазу.

**Плюсы аналогового кодирования**:
- Позволяет передавать сигнал на большие расстояния
- Возможность передавать множество независимых сигналов по одному каналу, разнеся их по разным частотам, например разные ТВ каналы
- Позволяет передать больше бит в секунду в ограниченной полосе частот, чем просто импульсная передача
**Минусы аналогового кодирования**:
- Сложность оборудования и их стоимость. Требуются генераторы частот, смесители, фильтры и демодуялторы
- Необходимость в том что модулятор и демодулятор должны быть настроены на одну частоту
- Усилители мощности вносят искажения в аналоговый сигнал, что требует высококлассных копмопнентов

**Основные виды цифровой модуляции:**
- **ASK** — амплитудная манипуляция;
	Плюсы:
	- Простая реализация и дешёвая, занимает узкую полосу
	Минусы
	- Крайне низкая помехоустойчивость, любая помеха меняет амплитуду, что приводит к ошибкам
	- Неэффективное использование мощности 
- **FSK** — частотная манипуляция;
	Плюсы:
	- Высокая помехоустойчивость, так как шум влияет на амплитуду, а не частоту
	- Простая реализация
	Минусы:
	- низкая скорость по сравнению с фазовой
	- требует широкой полосы частот
- **PSK** — фазовая манипуляция;
	Плюсы:
	-  **Лучшая помехоустойчивость** среди всех видов (для одинаковой мощности сигнала вероятность ошибки ниже, чем у ASK и FSK).
	- Постоянная огибающая (амплитуда не меняется), что позволяет использовать экономичные нелинейные усилители.
	Минусы:
	- Сложность реализации (требуется когерентный детектор, который точно знает опорную фазу).
	- Проблема «обратной работы» (инверсия фазы) — решается дифференциальной кодировкой (DPSK), но это снижает помехоустойчивость.
- **QAM** — одновременное изменение амплитуды и фазы. [Видео](https://www.youtube.com/watch?v=8tAxhV3GeGc&t=46s). [Визуализация синусоиды](https://www.getlykke.com/interactive/unit-circle-to-sine-wave-visualizer/precalculus-2e)
	Плюсы:
	- **Максимальная скорость передачи** в ограниченной полосе частот. Например, QAM-256 в 6 раз быстрее BPSK при той же полосе.
	- Широко стандартизирована (QAM-16, 64, 256, 1024).
	Минусы:
	- **Огромная чувствительность к шумам и искажениям.** Чтобы отличить близко расположенные точки сигнального созвездия, нужно очень высокое отношение сигнал/шум (SNR).
	- **Требует линейных усилителей** (класс A или AB), которые имеют низкий КПД и греются, иначе межсимвольные искажения разрушают сигнал.



Модуляция применяется в Wi-Fi, мобильных сетях, модемах, DSL, радиоканалах, современных высокоскоростных вариантах Ethernet.

### 2 Ступень: Помехоустойчивое кодирование

**Помехоустойчивое кодирование** — добавление проверочных бит для обнаружения или исправления ошибок, появившихся в канале. В отличие от логического кодирования, его цель — не синхронизация, а восстановление данных после помехи.

Надо различать:

- **FEC** (*Forward Error Correction*) — приёмник исправляет ошибку сам.
- **CRC + ARQ** — приёмник только обнаруживает ошибку и запрашивает повтор. CRC не является FEC.

#### Повторный код

**Алгоритм:** каждый бит повторяется нечётное число раз. Приёмник выбирает значение, встретившееся чаще.

```text
кодер:       1 → 111
канал:            101
декодер:          1  (две единицы из трёх)
```

**Плюсы:** максимально простой; исправляет одну ошибку в тройке.

**Минусы:** очень большая избыточность: из 3 переданных бит полезен только 1; плохо подходит для реальных быстрых сетей.

#### Код Хэмминга (7,4)

Кодирует 4 бита данных в 7 бит и исправляет **одну** ошибку.

**Кодирование:** проверочные биты ставятся на позиции, равные степеням двойки: `1`, `2`, `4`. Данные — на остальные позиции: `3`, `5`, `6`, `7`.

```text
позиция:  1   2   3   4   5   6   7
бит:      P1  P2  D1  P4  D2  D3  D4
```

Каждый проверочный бит — XOR определённых позиций:

- `P1` проверяет `1, 3, 5, 7`;
- `P2` проверяет `2, 3, 6, 7`;
- `P4` проверяет `4, 5, 6, 7`.

**Декодирование:** приёмник заново проверяет три группы. Результаты `S4 S2 S1` образуют двоичный номер ошибочной позиции. Например, `S4 S2 S1 = 110₂ = 6`: ошибка в 6-м бите, его надо инвертировать.

**Плюсы:** из 7 бит 4 полезные; точно указывает позицию одиночной ошибки; простая аппаратная реализация.

**Минусы:** две ошибки могут дать неверное исправление. Расширенный код Хэмминга добавляет ещё один общий проверочный бит: тогда две ошибки можно обнаружить, но не исправить.

#### CRC + повторная передача

CRC не исправляет данные, но почти всегда надёжно замечает повреждённый кадр.

**Алгоритм:** передатчик делит битовую последовательность на заранее выбранный полином по модулю 2 и дописывает остаток — CRC. Приёмник выполняет то же деление: ненулевой остаток означает ошибку → кадр отбрасывается → отправляется запрос на повтор.

**Плюсы:** маленькая избыточность; хорошо обнаруживает одиночные и пакетные ошибки; простая реализация.

**Минусы:** не исправляет ошибку; повтор увеличивает задержку и невозможен там, где обратного канала нет.

#### Код Рида — Соломона (Reed–Solomon)

Работает не с отдельными битами, а с символами (обычно байтами). Из `k` символов данных формируется `n` символов; `n − k` — проверочные.

**Алгоритм:** кодер вычисляет проверочные символы так, чтобы кодовое слово удовлетворяло набору уравнений. Декодер по нарушенным уравнениям находит позиции испорченных символов и их правильные значения. Если добавлено `p` проверочных символов, можно исправить до `p/2` неизвестно испорченных символов.

**Плюсы:** хорошо исправляет пакетные ошибки — например, повреждённый участок на диске или несколько потерянных байтов в канале.

**Минусы:** сложнее Хэмминга; работает с блоками и требует больше вычислений.

#### Свёрточные коды

**Алгоритм:** кодер хранит несколько последних битов в сдвиговом регистре и на каждый входной бит выдаёт несколько XOR от его содержимого. Поэтому выход зависит и от текущего, и от предыдущих битов. Декодер Витерби перебирает допустимые пути состояний и выбирает путь, наиболее похожий на принятый сигнал.

**Плюсы:** хорошо работают при случайных ошибках; декодер использует не только `0/1`, но и «насколько уверенно» принят бит.

**Минусы:** задержка и вычислительная сложность растут с числом состояний. В новых системах их часто заменяют Turbo-кодами и LDPC.

#### Выбор кода

Больше проверочных бит → выше защита, но ниже полезная скорость. Поэтому система выбирает код вместе с модуляцией: хороший канал → меньше избыточности и более плотная QAM; плохой канал → более сильный код и менее плотная модуляция.

### 1 Ступень: Логическое кодирование

Логическое кодирование выполняется **до** физического на том же физическом уровне модели OSI. Его главная цель - **преобразовать исходный поток данных** таким образом, чтобы он был удобен для последующего физического кодирования. 

Оно решает две глобальные задачи:
1. **Борьба с длинными сериями нулей или единиц** (проблема синхронизации для NRZ, NRZI, MLT-3).
2. **Исключение постоянной составляющей (DC-смещения)**, которая мешает работе трансформаторов и усилителей.
3. **Обнаружение ошибок** на раннем этапе (некоторые коды запрещают определенные комбинации).

Существует два основных подхода к логическому кодированию: **избыточное кодирование** (блочное) и **скремблирование**.

#### Избыточные коды (Блочное кодирование / Block Coding)

Этот метод основан на замене исходной битовой группы на группу большей длины. 

**Как это работает:**
Исходный поток разбивается на **символы** (группы бит) фиксированной длины, например, по 4 бита. Каждая такая группа заменяется на другую группу, которая содержит больше бит (например, 5 бит). Избыточность (лишние биты) позволяет выбрать только те кодовые слова, которые гарантируют нужное количество переходов.

**Самый известный пример — код 4B/5B (используется в Fast Ethernet 100BASE-TX, FDDI):**
- На входе 4 бита данных (16 комбинаций).
- На выходе 5 бит (32 комбинации). 
- Из 32 возможных комбинаций выбираются только 16 "хороших" (в которых нет трех нулей подряд и не более двух единиц подряд).
- Оставшиеся 16 комбинаций либо запрещены, либо используются как служебные сигналы (например, `J`, `K` для начала пакета).

*Почему это круто:* После кодирования 4B/5B данные подаются на физическое кодирование NRZI. Поскольку в 5-битных группах гарантированно есть переходы, приемник всегда поддерживает синхронизацию.

**Другие варианты избыточных кодов:**
- **8B/10B** (используется в Gigabit Ethernet, SATA, PCI Express, Fibre Channel): кодирует 8 бит в 10. Обеспечивает баланс нулей и единиц (постоянная составляющая близка к нулю) и множество переходов. Избыточность — 25%.
- **64B/66B** (используется в 10-гигабитном и более быстром Ethernet): кодирует 64 бита в 66. Избыточность всего ~3%, но для синхронизации добавляются специальные заголовки переключения (01 или 10) в начале блока, а остальные биты скремблируются.

#### Скремблирование (Scrambling)

В отличие от избыточного кодирования, скремблирование **не увеличивает** количество передаваемых битов. Оно работает по другому принципу.

**Суть метода:**
Исходный битовый поток побитно складывается по модулю 2 (операция XOR) с **псевдослучайной последовательностью (PRBS — Pseudo-Random Binary Sequence)**. 

*Пример:*
Исходный поток:   `1 0 0 0 0 0 0 0 1`
Ключ (PRBS):      `1 0 1 1 0 1 0 1 1`
Результат (XOR):  `0 0 1 1 0 1 0 1 0`

**Механизм работы:**
- На передающей стороне стоит **скремблер** (генератор псевдослучайной последовательности + XOR).
- На приемной стороне стоит точно такой же генератор псевдослучайной последовательности (синхронизированный по тактам) и **дескремблер** (еще один XOR). 
- Если на приемнике повторно применить XOR с тем же самым ключом к принятому потоку, мы получим исходные данные: `(A XOR B) XOR B = A`.

**Свойства скремблирования:**
- **Преимущества:** Нет избыточности (скорость передачи не падает), хорошо "разбивает" длинные последовательности одинаковых бит, превращая их в меандр.
- **Недостатки:** Если на вход придет синхронная последовательность (например, все нули), на выходе скремблера получится просто копия псевдослучайного ключа — переходы будут, синхронизация спасена. Однако скремблирование **не гарантирует** отсутствие постоянной составляющей на 100%, в отличие от 8B/10B.
- **Важный нюанс:** Скремблирование — это детерминированный процесс. Ключ генерируется с помощью сдвигового регистра с обратной связью (LFSR). Если скремблер и дескремблер "разойдутся" по фазе (потеряют синхронизацию), биты будут декодироваться неверно, пока синхронизация не восстановится (для этого в кадре Ethernet есть преамбула).

**Примеры использования:**
- **NRZI + Скремблирование:** В стандарте USB 3.0 и SATA используется скремблирование перед NRZI, чтобы избежать длинных серий нулей.
- **Ethernet 10GBASE-R:** Использует код 64B/66B, но оставшиеся 64 бита данных **обязательно скремблируются**, чтобы распределить энергию сигнала по спектру и избежать помех на соседних каналах (эффект "молчащего" канала).
