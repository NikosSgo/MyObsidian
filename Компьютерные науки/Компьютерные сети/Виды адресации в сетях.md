Адресация отвечает на разные вопросы на разных уровнях: **к какому устройству в локальной сети**, **к какой сети в Интернете**, **к какой программе на устройстве** и **к какому ресурсу обращается пользователь**.

| Вид адреса             | Что адресует                                   | Пример                            | Уровень OSI      |
| ---------------------- | ---------------------------------------------- | --------------------------------- | ---------------- |
| Физический адрес (MAC) | Сетевой интерфейс в пределах одного канала/LAN | `00:1A:2B:3C:4D:5E`               | 2 — канальный    |
| Логический адрес (IP)  | Узел или его интерфейс в сети сетей            | `192.168.1.10`, `2001:db8::10`    | 3 — сетевой      |
| Порт                   | Программу/службу внутри узла                   | `443`, `53`                       | 4 — транспортный |
| Имя/прикладной адрес   | Ресурс, службу или пользователя                | `example.com`, `user@example.com` | 7 — прикладной   |

## MAC-адрес — доставка в локальной сети

MAC-адрес используется внутри одного сегмента сети: Ethernet или Wi‑Fi. Коммутатор по MAC-адресу решает, в какой порт отправить кадр.

```text
ПК → коммутатор → роутер
MAC назначения: MAC роутера
```

Если пакет идёт через роутер, на каждом участке меняются MAC-адреса кадра: отправитель ставит MAC следующего узла, а не MAC конечного сервера. IP-адрес при этом обычно остаётся адресом конечного узла.

**Важно:** MAC не обязательно «зашит навсегда» в устройство — его можно менять программно. Для поиска MAC по IPv4 в LAN используется ARP, по IPv6 — NDP.

## IP-адрес — доставка между сетями

IP-адрес нужен маршрутизаторам, чтобы довести пакет до нужной сети и узла. Он имеет иерархию: часть адреса обозначает сеть, часть — интерфейс в этой сети.

```text
IP назначения:  8.8.8.8      ← конечный узел
MAC назначения: MAC шлюза    ← следующий узел на текущем участке
```

IPv4 — 32 бита, например `192.168.1.10`. IPv6 — 128 бит, например `2001:db8::10`. Один узел может иметь несколько IP-адресов; публичный IP может быть преобразован NAT.

## Порт — доставка нужной программе

IP приводит пакет на компьютер, но не говорит, **какой процесс** должен его получить. Это определяет порт TCP или UDP.

```text
IP:порт = 93.184.216.34:443
```

Например, `443` обычно HTTPS, `53` — DNS, `22` — SSH. Пара `IP + порт + протокол` однозначно определяет сетевую конечную точку — **сокет**.

## Прикладной адрес — то, что видит пользователь

Пользователь обычно не вводит IP: он использует имя или идентификатор ресурса.

- DNS-имя `example.com` DNS преобразует в IP-адрес.
- URL `https://example.com/docs` содержит протокол, имя хоста и путь к ресурсу.
- Email `user@example.com` указывает почтовый ящик; доменная часть помогает найти почтовый сервер.

Это адреса уровня приложений: их формат и значение определяет конкретный протокол, а не сама IP-сеть.

## Не путать с типами доставки

Unicast, broadcast, multicast и anycast — не уровни адресов, а способы выбрать получателей:

- **Unicast** — одному получателю.
- **Broadcast** — всем в локальной сети; маршрутизаторы обычно не пересылают его дальше.
- **Multicast** — группе подписанных получателей.
- **Anycast** — одному из нескольких одинаково адресованных узлов, обычно ближайшему по маршрутизации.

## Полная цепочка

```text
https://example.com
        ↓ DNS
93.184.216.34:443
        ↓ IP-маршрутизация
MAC следующего узла
        ↓ Ethernet/Wi‑Fi
кадр передаётся по текущему локальному каналу
```
