### Стеки протоколов vs модель OSI

**Модель OSI (7 уровней):**
```
7. Прикладной     (HTTP, FTP, SMTP, DNS)
6. Представления  (SSL/TLS, JPEG, ASCII)
5. Сеансовый      (NetBIOS, RPC)
4. Транспортный   (TCP, UDP)
3. Сетевой        (IP, ICMP, ARP, OSPF)
2. Канальный      (Ethernet, Wi-Fi, PPP)
1. Физический     (Кабель, разъёмы, сигнал)
```

**Стек TCP/IP (4 уровня — de facto):**
```
4. Прикладной     (HTTP, FTP, SMTP, DNS, SSH) — ≈ OSI 5-7
3. Транспортный   (TCP, UDP) — ≈ OSI 4
2. Межсетевой     (IP, ICMP, ARP) — ≈ OSI 3
1. Сетевой доступ (Ethernet, Wi-Fi) — ≈ OSI 1-2
```

### Сетевые и транспортные протоколы TCP/IP

#### Сетевые (L3):
| Протокол | Функция |
|---|---|
| **IP** | Маршрутизация, адресация, фрагментация |
| **ICMP** | Диагностика (ping: Echo Request/Reply, TTL exceeded) |
| **ARP** | Разрешение IP → MAC-адрес (широковещательный запрос) |

#### Транспортные (L4):
| Протокол | Ориентация | Надёжность | Применение |
|---|---|---|---|
| **TCP** | Соединение | Да (ACK, re-transmit) | HTTP, SMTP, FTP |
| **UDP** | Без соединения | Нет (броадкаст) | DNS, VoIP, видео |

### Алгоритм скользящего окна (Sliding Window)

**Задача:** эффективная передача данных с подтверждением. Отправитель может отправить несколько пакетов без ожидания ACK.

**Параметры:**
- $W$ — размер окна (сколько пакетов можно отправить без ACK)
- $LAR$ — номер последнего подтверждённого пакета
- $SWS$ — send window size (размер окна отправителя)

**Работа:**
```
Отправитель: [ACKed] [SENT] [SENT][SENT] [CAN'T SEND YET]
             ↑ LAR        ↑ LFS         ↑ LAR + SWS
```
- При получении ACK: LAR сдвигается вправо
- При тайм-ауте: повторная отправка oldest unACKed

**Настройка размера окна:**
- Маленькое окно: низкая скорость (ждём ACK)
- Большое окно: риск перегрузки сети
- **TCP использует flow control (окно от получателя) + congestion control (алгоритм медленного старта, избегание перегрузки)**
