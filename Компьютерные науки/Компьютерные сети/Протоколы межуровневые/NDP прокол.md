**NDP** — набор сообщений ICMPv6, с помощью которых IPv6-узлы узнают соседей и роутеры в текущем локальном канале. По одной из задач NDP заменяет ARP, но умеет больше: обнаруживает роутеры, настраивает адреса и проверяет их уникальность.

```text
Ethernet/Wi‑Fi кадр → IPv6-пакет → ICMPv6-сообщение NDP
```

Формально NDP находится на L3: это ICMPv6 внутри IPv6. По назначению он работает на границе L2/L3, потому что связывает IPv6-адрес соседа с его канальным адресом (обычно MAC).

## Что делает NDP

| Задача                | Что делает NDP                                             |
| --------------------- | ---------------------------------------------------------- |
| Поиск соседа          | сопоставляет IPv6-адрес соседа с его MAC/канальным адресом |
| Поиск роутера         | находит default gateway в LAN                              |
| Автонастройка         | получает префикс и параметры сети для SLAAC                |
| Проверка уникальности | убеждается, что IPv6-адрес ещё никем не занят (DAD)        |
| Проверка доступности  | отслеживает, отвечает ли сосед (NUD)                       |
| Оптимизация пути      | роутер может подсказать лучший next hop (Redirect)         |

## Основные сообщения NDP

Все они — ICMPv6.

| Сообщение | Тип ICMPv6 | Кто отправляет | Зачем |
| --- | --- | --- |
| Router Solicitation (RS) | 133 | хост | «Есть ли здесь роутеры? Пришлите параметры» |
| Router Advertisement (RA) | 134 | роутер | префикс IPv6, шлюз, MTU, время жизни и параметры SLAAC |
| Neighbor Solicitation (NS) | 135 | хост/роутер | «У кого этот IPv6? Сообщите свой MAC»; также DAD/NUD |
| Neighbor Advertisement (NA) | 136 | владелец адреса | ответ на NS: «этот IPv6 мой, вот мой MAC» |
| Redirect | 137 | роутер | «К этой цели лучше отправлять через другой next hop» |

## NDP как замена ARP

Пусть хост `2001:db8:1::10` хочет передать пакет соседу `2001:db8:1::20`.

1. Хост проверяет **neighbor cache** — аналог ARP-кэша.
2. Если соответствия IPv6 → MAC нет, он отправляет **Neighbor Solicitation**.
3. NS идёт не broadcast, а на специальный *solicited-node multicast* адрес цели `ff02::1:ffXX:XXXX`.
4. Владелец IPv6 отвечает **Neighbor Advertisement**, обычно unicast.
5. Хост сохраняет пару в кэше и формирует обычный L2-кадр на полученный MAC.

```text
IPv6 next hop:  2001:db8:1::20
        ↓ NDP
MAC next hop:   BB:BB:BB:BB:BB:BB
```

NDP работает только на текущем канале: его пакеты имеют link-local scope, а IPv6 Hop Limit должен быть `255`. Роутер не пересылает такие сообщения в другую LAN.

## Поиск роутера и SLAAC

В IPv4 хост часто получает IP, маску и шлюз по DHCP. В IPv6 адрес можно настроить без DHCPv6 через **SLAAC** (*Stateless Address Autoconfiguration*).

```text
хост → RS → all-routers multicast ff02::2
роутер → RA → префикс 2001:db8:1::/64, MTU, default gateway
хост → создаёт IPv6-адрес из префикса + идентификатора интерфейса
```

RA может приходить периодически и без RS. Из RA хост узнаёт:

- какие IPv6-префиксы доступны в LAN;
- какой роутер использовать по умолчанию;
- MTU канала;
- можно ли формировать адрес через SLAAC;
- нужен ли DHCPv6 для дополнительных параметров;
- при наличии расширений — DNS-серверы и поисковый домен.

## DAD: проверка уникальности адреса

Перед использованием нового IPv6-адреса хост делает **Duplicate Address Detection**.

1. Хост ещё не назначает адрес интерфейсу окончательно.
2. Он посылает NS для проверяемого адреса; источник — `::` (неуказанный адрес).
3. Если кто-то ответит NA, адрес уже занят → использовать его нельзя.
4. Нет ответа → адрес считается уникальным и становится рабочим.

Это нужно для SLAAC, вручную заданных адресов и после смены интерфейса.

## NUD: проверка доступности соседа

Запись в neighbor cache не вечная. Если хост давно не видел подтверждения от соседа, он отправляет NS и ждёт NA. Если ответа нет, запись помечается недоступной, и ОС пытается заново найти соседа или выбрать другой маршрут.

В ARP обычно кэш просто устаревает по таймеру; NDP использует более полную модель состояний соседей.

## NDP и удалённые сети

Как и ARP, NDP не ищет MAC удалённого сервера. Сначала IPv6-маршрутизация выбирает next hop:

| IP-пакет идёт | Для кого NDP ищет MAC |
| --- | --- |
| К IPv6-соседу в той же LAN | для конечного узла |
| В удалённую IPv6-сеть | для default gateway / выбранного роутера |

```text
IPv6 назначения пакета:  2001:4860:4860::8888
next hop:                 fe80::1  (локальный адрес роутера)
NDP ищет:                 MAC роутера fe80::1
```

## Отличия от ARP

| ARP | NDP |
| --- | --- |
| Только IPv4 | Только IPv6 |
| Напрямую в Ethernet-кадре, EtherType `0x0806` | ICMPv6 внутри IPv6-пакета |
| Broadcast Request | Multicast NS к группе цели |
| В основном IPv4 → MAC | адресное разрешение + роутеры + SLAAC + DAD + NUD |
| Простая ARP-таблица | neighbor cache со состояниями |

## Безопасность

NDP, как и ARP, по умолчанию не доказывает подлинность отправителя. Ложный RA может назначить атакующий роутер, а ложный NA — подменить MAC соседа.

Защита: RA Guard и DHCPv6 Guard на коммутаторах, фильтрация ICMPv6, сегментация VLAN; в специальных сетях — SEND (*Secure Neighbor Discovery*). Полностью блокировать ICMPv6 нельзя: без него ломаются NDP и нормальная работа IPv6.
