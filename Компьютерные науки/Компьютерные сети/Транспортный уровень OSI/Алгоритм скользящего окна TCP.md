**Скользящее окно TCP** позволяет отправителю передать несколько байтов или сегментов подряд, не дожидаясь ACK после каждого. Так канал не простаивает во время ожидания ответа.

Отправитель может послать только данные, попадающие в текущее окно. Когда приходит ACK, левая граница окна сдвигается вперёд — появляются места для новых данных.

## Пример работы

Пусть клиент начинает передачу с номера `1001`, а сервер готов принять 3000 байт:

```text
окно клиента: [1001 ................................ 4000]
```

1. Клиент сразу отправляет три сегмента по 1000 байт: `SEQ = 1001`, `2001`, `3001`.
2. Сервер получил первый сегмент и отвечает `ACK = 2001`: «все байты до 2000 получены, жду 2001».
3. Окно сдвигается:

   ```text
   новое окно: [2001 ................................ 5000]
   ```

4. Клиент может отправить ещё 1000 байт с `SEQ = 4001`, даже если остальные ACK ещё в пути.

Если сегмент с `SEQ = 2001` потеряется, сервер продолжит отвечать `ACK = 2001`: он ждёт пропущенные байты. Отправитель повторит сегмент по таймеру или после нескольких одинаковых ACK. SACK может дополнительно сообщить, что более поздние сегменты уже пришли.

## Основные параметры

- **Sequence Number** — номер первого байта в сегменте; задаёт положение данных в потоке.
- **Acknowledgment Number** — номер следующего ожидаемого байта; сдвигает окно отправителя.
- **Receive Window (`rwnd`)** — свободное место в буфере получателя. Передаётся в поле **Window Size** каждого TCP-сегмента и защищает получателя от переполнения.
- **Congestion Window (`cwnd`)** — ограничение отправителя из-за перегрузки сети. Это внутреннее состояние TCP, в заголовке оно не передаётся.
- **Send Window** — реальный объём данных, который можно отправить без ACK: `min(rwnd, cwnd)`.
- **Window Scale** — TCP Option, согласуемая в SYN. Увеличивает 16-битное поле Window Size для высокоскоростных сетей с большой задержкой.
- **MSS** (*Maximum Segment Size*) — максимальный размер данных в одном TCP-сегменте. Это не размер окна: окно может содержать много сегментов MSS.

## Важные состояния

- **Нулевое окно** — получатель временно не имеет места в буфере и объявляет `Window Size = 0`. Отправитель останавливает передачу и иногда посылает маленький *window probe*, чтобы узнать, открылось ли окно.
- **Маленькое окно** — уменьшает скорость передачи: даже быстрый канал будет простаивать, если отправитель быстро заполняет доступное окно.
- **Большое окно** — особенно важно при большой задержке. Ориентир: чтобы заполнить канал, окно должно быть не меньше произведения пропускной способности на RTT (*bandwidth-delay product*).
