**Статическая маршрутизация** — маршруты, которые администратор добавляет в таблицу вручную.

```text
сеть назначения: 10.20.0.0/16
следующий узел:  192.168.1.1
```

Роутер использует такую запись, пока её не изменят или не удалят. Она не перестраивается при отказе канала.

## Что задаёт администратор

- **Сеть назначения** — к каким адресам относится маршрут: `10.20.0.0/16`.
- **Next hop** — IP следующего роутера: `192.168.1.1`. Роутер узнаёт его MAC через ARP/NDP и отправляет ему кадр.
- **Выходной интерфейс** — через какой порт передавать пакет: например, `eth0`.
- **Метрика** — предпочтение маршрута, если есть несколько одинаковых префиксов: меньше — лучше.

В Linux такой маршрут выглядит так:

```bash
ip route add 10.20.0.0/16 via 192.168.1.1 dev eth0
```

## Основные виды

- **Маршрут к сети** — путь к целой сети, например `10.20.0.0/16`.
- **Маршрут к узлу** — путь к одному адресу: `10.20.5.10/32` в IPv4 или `/128` в IPv6.
- **Маршрут по умолчанию** — `0.0.0.0/0`; используется, когда нет более точного маршрута. Обычно ведёт на интернет-шлюз.
- **Резервный (floating static route)** — статический маршрут с большей метрикой. Он начнёт использоваться, только если основной маршрут исчезнет из таблицы.

## При отказе канала

Статический маршрут не ищет обходной путь сам. Если next hop или канал недоступен, пакеты могут теряться, пока администратор не изменит таблицу или не сработает заранее настроенный резервный маршрут. Поэтому статические маршруты удобны для небольших, тупиковых и стабильных сетей; в сложной сети их обычно дополняют [[Динамическая маршрутизация|динамической маршрутизацией]].

**Плюсы:** предсказуемость, простота и отсутствие служебного трафика.

**Минусы:** ручная настройка и плохая масштабируемость. Подходит для небольших или тупиковых сетей, а также для маршрута по умолчанию (`0.0.0.0/0`).
