Устройству нужен не только IP-адрес, но и префикс/маска, шлюз по умолчанию и обычно DNS-сервер. Их можно задать вручную или получить автоматически.

## Статическая настройка

Администратор вручную задаёт IP-адрес, маску (префикс), шлюз и DNS. Подходит для серверов, роутеров и устройств, которым нужен постоянный адрес. Нужно следить, чтобы два устройства не получили один и тот же IP.

## IPv4: DHCP

**DHCP** (*Dynamic Host Configuration Protocol*) автоматически выдаёт настройки на ограниченное время — *lease*. Это прикладной протокол, работающий поверх UDP: сервер использует порт `67`, клиент — `68`.

1. **Discover** — клиент без адреса отправляет broadcast: «есть DHCP-сервер?»
2. **Offer** — сервер предлагает свободный IP и параметры.
3. **Request** — клиент запрашивает выбранное предложение.
4. **ACK** — сервер подтверждает аренду; клиент настраивает интерфейс.

Обычно DHCP передаёт IP-адрес, маску, шлюз, DNS и срок аренды.

### Где находится DHCP-сервер и как его находят

- Дома DHCP-сервером обычно является роутер. В организации это может быть Windows Server, Linux-сервер, firewall или отдельное сетевое устройство.
- Клиент уже подключён к локальной сети на L2: кабель вставлен или Wi‑Fi-соединение установлено. IP ему ещё не нужен, чтобы отправить DHCP Discover.
- Discover отправляется broadcast-кадром в текущем VLAN: IP назначения `255.255.255.255`, MAC назначения `FF:FF:FF:FF:FF:FF`. Коммутатор разошлёт его по этой сети, и DHCP-сервер ответит.
- Роутеры broadcast не пересылают. Если сервер находится в другой подсети, на роутере настраивают **DHCP relay** (*IP helper*): он принимает broadcast клиента и пересылает запрос серверу уже unicast-пакетом.

### Что происходит с арендой

- Адрес выдаётся не навсегда, например на 24 часа.
- Примерно после 50% времени аренды клиент пытается продлить её, отправляя DHCP Request прежнему серверу unicast.
- Если сервер не отвечает, примерно после 87,5% времени клиент отправляет broadcast-запрос: возможно, ответит другой DHCP-сервер.
- После окончания аренды клиент перестаёт использовать адрес. Текущие соединения обрываются, затем клиент снова ищет DHCP-сервер или получает APIPA.

## APIPA / IPv4 link-local

**APIPA** (*Automatic Private IP Addressing*) — название Windows для автоматического IPv4 link-local адреса. Он используется, когда DHCP-сервер недоступен.

- Устройство случайно выбирает адрес из `169.254.1.0–169.254.254.255` с маской `/16`.
- Перед назначением отправляет ARP Probe: если адрес уже занят, выбирает другой.
- Такой адрес не маршрутизируется и обычно не даёт шлюз или DNS, поэтому работать можно только с устройствами текущей локальной сети.
- ОС продолжает периодически искать DHCP. Как только сервер ответит, APIPA заменяется обычной DHCP-настройкой.

## IPv6: SLAAC и DHCPv6

IPv6-интерфейс сначала сам создаёт link-local адрес из `fe80::/10`. Затем возможны два способа:

- **SLAAC** (*Stateless Address Autoconfiguration*) — роутер периодически отправляет Router Advertisement (RA) через NDP/ICMPv6. В RA есть префикс сети и шлюз; устройство само формирует IPv6-адрес.
- **DHCPv6** — сервер выдаёт IPv6-адрес и/или дополнительные параметры, например DNS. Он может работать вместе со SLAAC.

Шлюз по умолчанию IPv6 устройство получает именно из RA, а не из DHCPv6.
