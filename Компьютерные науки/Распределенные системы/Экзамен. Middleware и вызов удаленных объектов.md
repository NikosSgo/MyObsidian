### Middleware (программное обеспечение промежуточного уровня)

**Middleware** — ПО, работающее между ОС и приложениями, обеспечивающее взаимодействие в распределённой системе.

**Функции:**
- Сокрытие гетерогенности сетей, ОС, языков
- Управление транзакциями
- Балансировка нагрузки
- Безопасность (аутентификация, шифрование)
- Обнаружение сервисов (service discovery)

**Технологии Middleware:**

| Тип | Пример | Описание |
|---|---|---|
| **RPC (Remote Procedure Call)** | gRPC, Apache Thrift | Вызов функции на удалённом узле как локальной |
| **Message-Oriented** | RabbitMQ, Kafka, ActiveMQ | Асинхронная передача сообщений через брокер |
| **Object Brokers** | CORBA, DCOM, Java RMI | Удалённый вызов методов объектов |
| **Web Services** | SOAP, REST, GraphQL | HTTP-based взаимодействие |
| **Database Middleware** | ODBC, JDBC | Единый доступ к разным БД |

### Схема вызова удалённых объектов (RPC/RMI)

```
Клиент                     Сервер
   │                          │
   │ 1. Вызов метода          │
   ├─→ Клиентская заглушка    │
   │   (Stub/Proxy)           │
   ├─→ Marshalling (сериализация)
   ├─→ Сетевое взаимодействие │
   │   (TCP/UDP/HTTP)         │
   │                     ┌────┴─→ Серверная заглушка
   │                     │        (Skeleton)
   │                     ├─────→ Распаковка (unmarshalling)
   │                     ├─────→ Вызов реального объекта
   │                     ├─────→ Результат → marshalling
   │←─── Ответ ←─────────┘
   │
   └─→ Распаковка → результат
```

**Пример (gRPC):**
```protobuf
service UserService {
    rpc GetUser (UserRequest) returns (UserResponse)
}
```
Клиент вызывает `GetUser()` как локальную функцию, gRPC превращает это в HTTP/2 запрос.
