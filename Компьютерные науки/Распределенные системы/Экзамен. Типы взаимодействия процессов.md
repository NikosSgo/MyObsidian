# Типы взаимодействия процессов

## Cooperative vs Competing процессы

### Cooperating (сотрудничающие)
Процессы обмениваются данными и влияют на результаты друг друга.

**Преимущества:**
- Ускорение выполнения (параллелизм)
- Разделение ресурсов
- Модульность

**Недостатки:**
- Сложность синхронизации
- Возможность ошибок (onerace condition)

### Competing (конкурирующие)
Процессы борются за общие ресурсы.

**Последствия:**
- Race condition
- Невоспроизводимость результатов

## Межпроцессное взаимодействие (IPC)

### Разделяемая память (Shared Memory)
- Процессы читают/пишут в общую область памяти
- Высокая скорость, но требует синхронизации
- Пример: `mmap`, POSIX shared memory

### Передача сообщений (Message Passing)
- Процессы обмениваются сообщениями через системные вызовы
- Не требует разделяемой памяти
- Пример: `pipe`, `socket`, MPI

## Классические задачи синхронизации

### Producer-Consumer (производитель-потребитель)
- **Производитель** создаёт данные, помещает в буфер
- **Потребитель** извлекает и обрабатывает
- Проблема: переполнение / опустошение буфера
- Решение: семафоры (full, empty, mutex)

### Reader-Writer (читатель-писатель)
- Множество читателей, один писатель
- Читатели могут работать параллельно
- Писатель требует эксклюзивного доступа
- Варианты: с приоритетом читателей, писателей или справедливый

### Dining Philosophers (стол философов)
- 5 философов, 5 вилок (ресурсов)
- Мёртвая блокировка при неосторожном захвате
- Решение: иерархическая нумерация ресурсов, таймауты

## Проблемы при взаимодействии
| Проблема | Описание |
|----------|----------|
| Race condition | Результат зависит от порядка выполнения |
| Deadlock | Взаимная блокировка процессов |
| Starvation | Процесс не получает ресурс бесконечно |
| Livelock | Процессы активны, но не продвигаются вперёд |
