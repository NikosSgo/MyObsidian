**Рекурсивный алгоритм** решает задачу, вызывая себя для одного или нескольких входов меньшего размера. Он должен содержать:
- базовый случай, вычисляемый без рекурсивного вызова;
- рекурсивный случай, сводящий задачу к меньшим подзадачам;
- условие, гарантирующее приближение к базовому случаю.

Для анализа необходимо определить:
- размер задачи $n$;
- количество рекурсивных вызовов;
- размер каждой подзадачи;
- работу, выполняемую вне рекурсивных вызовов;
- глубину рекурсии и память одного вызова.

Временную сложность рекурсивного алгоритма описывают **рекуррентным уравнением**, связывающим значение $T(n)$ со сложностью меньших задач. Для завершённого определения также задаётся начальное условие, например $T(1)=\Theta(1)$.

Общий вид рекуррентного уравнения для алгоритма «разделяй и властвуй»:

$$
T(n)=aT\left(\frac{n}{b}\right)+f(n),
$$

где:
- $a$ — количество рекурсивных подзадач;
- $n/b$ — размер каждой подзадачи;
- $f(n)$ — работа по разбиению задачи, обработке текущего вызова и объединению результатов.

**Линейная рекурсия** — рекурсия, при которой один вызов функции порождает не более одного следующего рекурсивного вызова. Цепочка вызовов не ветвится.

Например, вычисление факториала:

```python
def factorial(n):
    if n <= 1:
        return 1
    return n * factorial(n - 1)
```

Каждый вызов уменьшает $n$ на единицу и выполняет постоянное количество дополнительной работы:

$$
T(n)=T(n-1)+\Theta(1),
\qquad T(1)=\Theta(1).
$$

Последовательная подстановка даёт:

$$
T(n)=T(n-2)+2\Theta(1)=\ldots=T(1)+(n-1)\Theta(1),
$$

поэтому $T(n)=\Theta(n)$.

Глубина рекурсии также равна $n$, а каждый вызов занимает постоянный объём стека:

$$
S_{aux}(n)=\Theta(n).
$$

Линейная рекурсия не обязательно имеет линейную временную сложность. Если размер задачи делится на два, глубина становится логарифмической:

```python
def binary_search(data, target, left, right):
    if left > right:
        return -1
    middle = (left + right) // 2
    if data[middle] == target:
        return middle
    if data[middle] < target:
        return binary_search(data, target, middle + 1, right)
    return binary_search(data, target, left, middle - 1)
```

$$
T(n)=T(n/2)+\Theta(1)=\Theta(\log n),
$$

$$
S_{aux}(n)=\Theta(\log n).
$$

Если один рекурсивный вызов уменьшает размер на единицу, но вне него выполняется линейная работа, получаем:

$$
T(n)=T(n-1)+\Theta(n)
=\sum_{i=1}^{n}\Theta(i)
=\Theta(n^2).
$$

**Нелинейная, или ветвящаяся, рекурсия** — рекурсия, при которой один вызов порождает несколько рекурсивных вызовов. Выполнение образует дерево рекурсии.

Наивное вычисление чисел Фибоначчи:

```python
def fibonacci(n):
    if n <= 1:
        return n
    return fibonacci(n - 1) + fibonacci(n - 2)
```

Ему соответствует уравнение:

$$
T(n)=T(n-1)+T(n-2)+\Theta(1).
$$

Число вызовов растёт экспоненциально:

$$
T(n)=\Theta(\varphi^n)=O(2^n),
$$

где $\varphi=(1+\sqrt5)/2$ — золотое сечение. Причина — многократное решение одинаковых подзадач. Мемоизация сохраняет их результаты и уменьшает время до $\Theta(n)$, используя $\Theta(n)$ дополнительной памяти.

Сортировка слиянием создаёт две подзадачи половинного размера, после чего за линейное время объединяет результаты:

$$
T(n)=2T(n/2)+\Theta(n).
$$

На каждом уровне дерева суммарно обрабатывается $\Theta(n)$ элементов, а высота дерева равна $\Theta(\log n)$. Поэтому:

$$
T(n)=\Theta(n\log n).
$$

Количество рекурсивных вызовов нельзя механически отождествлять с расходом памяти. Если ветви вычисляются последовательно, завершённый вызов освобождается до завершения всего алгоритма, поэтому стек определяется максимальной глубиной дерева, а не общим числом его узлов.

Например:
- наивный алгоритм Фибоначчи работает за экспоненциальное время, но глубина его стека равна $\Theta(n)$;
- сортировка слиянием имеет глубину стека $\Theta(\log n)$, но вспомогательные массивы требуют в сумме $\Theta(n)$ памяти.

Основные методы решения рекуррентных уравнений:
- **развёртывание, или итерация** — несколько раз подставить рекуррентное выражение в само себя и обнаружить закономерность;
- **метод подстановки** — предположить асимптотическую оценку и доказать её по индукции;
- **дерево рекурсии** — определить работу на каждом уровне и просуммировать её по всем уровням;
- **основная теорема о рекурсии** — применить готовую оценку к уравнению вида $aT(n/b)+f(n)$.

При развёртывании уравнения

$$
T(n)=T(n/2)+\Theta(1)
$$

после $k$ подстановок получается:

$$
T(n)=T(n/2^k)+k\Theta(1).
$$

Базовый случай достигается при $n/2^k=1$, то есть $k=\log_2n$. Следовательно, $T(n)=\Theta(\log n)$.

Для применения основной теоремы сравнивают $f(n)$ с количеством работы, создаваемой рекурсивными подзадачами:

$$
n^{\log_ba}.
$$

Основные случаи:
- если $f(n)$ полиномиально меньше $n^{\log_ba}$, то $T(n)=\Theta(n^{\log_ba})$;
- если $f(n)=\Theta(n^{\log_ba})$, то $T(n)=\Theta(n^{\log_ba}\log n)$;
- если $f(n)$ полиномиально больше $n^{\log_ba}$ и выполняется условие регулярности, то $T(n)=\Theta(f(n))$.

Например, для сортировки слиянием $a=2$, $b=2$, $f(n)=\Theta(n)$:

$$
n^{\log_22}=n.
$$

Функции имеют одинаковый порядок, поэтому применяется второй случай:

$$
T(n)=\Theta(n\log n).
$$

Основная теорема неприменима напрямую к уравнениям вида $T(n)=T(n-1)+f(n)$, к подзадачам разного размера и к некоторым нерегулярным функциям $f(n)$. В таких случаях используют развёртывание, суммы, дерево рекурсии или более общие методы.

При анализе рекурсивного алгоритма важно отдельно проверить:
- корректность базового случая;
- уменьшение размера задачи и завершение рекурсии;
- временную сложность всех рекурсивных ветвей;
- максимальную глубину стека;
- память, выделяемую внутри каждого вызова;
- наличие одинаковых подзадач, которые можно устранить мемоизацией.
