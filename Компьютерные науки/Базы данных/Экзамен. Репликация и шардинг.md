# Экзамен. Репликация и шардинг

## Репликация

### Определение
Создание и поддержание **копий данных** на нескольких узлах для повышения отказоустойчивости и читаемой пропускной способности.

### Master-Slave (Лидер-Последователь)

- **Master** — единственный узел для записи
- **Slave** — реплики для чтения, получают данные от master
- Синхронная: slave подтверждает запись master → **высокая consistency**, низкая производительность
- Асинхронная: master не ждёт подтверждения → **высокая производительность**, риск потери данных при сбое master

### Master-Master (Мульти-мастер)

- Любой узел может читать и писать
- Синхронизация через **conflict resolution** (timestamp, версии, приоритет)
- Плюсы: высокая доступность, нет единой точки отказа
- Минусы: сложность разрешения конфликтов, задержки репликации

### Синхронная vs Асинхронная репликация

| Критерий | Синхронная | Асинхронная |
|----------|-----------|-------------|
| Consistency | Строгая (strong) | eventual |
| Задержка записи | Высокая | Низкая |
| Потеря данных | Невозможна | Возможна |
| Доступность | Низкая | Высокая |
| Использование | Финансы, инвентарь | Логи, аналитика |

### Примеры систем
- **PostgreSQL** — streaming replication (синхронная/асинхронная)
- **MySQL** —主从复制 (binlog)
- **MongoDB** — replica sets (oplog)

## Шардинг (Sharding)

### Определение
**Горизонтальное разделение** данных по нескольким серверам (шардам) по ключу шардинга.

### Shard Key — ключ шардинга

Выбор критически важен:
- **Равномерное распределение** — избежать hotspot
- **Частый доступ по ключу** — чтобы запросы шли в один шард
- Плохой ключ: `user_id` при неравномерном распределении, `timestamp` → hotspot на последнем шарде

### Типы шардинга

**Hash-based:**
```
shard = hash(shard_key) % num_shards
```
- Равномерное распределение, но диапазонные запросы идут во все шарды

**Range-based:**
```
shard = shard_key в диапазоне [min, max]
```
- Диапазонные запросы эффективны, но возможны hotspot

**Consistent Hashing:**
- Узлы и ключи на **кольце**, каждому ключу — ближайший узел по часовой стрелке
- При добавлении/удалении узла перехешируется только часть данных (~1/n)
- Используется в: Cassandra, DynamoDB, Memcached

### Плюсы и минусы шардинга

| Преимущества | Недостатки |
|--------------|-----------|
| Горизонтальное масштабирование | Сложность запросов跨 шарды |
| Высокая пропускная способность | Дistributed транзакции (2PC, saga) |
| Изоляция нагрузки | Ребалансировка при добавлении шардов |
| Локализация данных | Потеря JOIN между шардами |

### Сравнение репликации и шардинга

| Критерий | Репликация | Шардинг |
|----------|-----------|---------|
| Цель | Отказоустойчивость, чтение | Масштабирование записи/хранилища |
| Данные | Полная копия на каждом узле | Каждый узел — часть данных |
| Сложность | Низкая | Высокая |
| Consistency | Реплики могут отставать | Транзакции跨 шарды |
