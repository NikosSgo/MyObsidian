# Транзакции в базах данных

## Определение
**Транзакция** — логическая единица работы с БД, состоящая из одного или нескольких запросов.

## ACID-свойства

| Свойство | Описание |
|----------|----------|
| **Atomicity** (атомарность) | Транзакция выполняется полностью или не выполняется вообще |
| **Consistency** (согласованность) | После транзакции БД остаётся в консистентном состоянии |
| **Isolation** (изоляция) | Параллельные транзакции не влияют друг на друга |
| **Durability** (долговечность) | Результат зафиксированной транзакции сохраняется |

## Состояния транзакции

```
  active
    ↓
partially committed
    ↓         ↘
 committed    failed
                ↓
              aborted
```

- **Active** — выполняется
- **Partially committed** — все операции выполнены, ожидается фиксация
- **Failed** — обнаружена ошибка
- **Aborted** — откачена, изменения отменены (ROLLBACK)
- **Committed** — успешно завершена (COMMIT)

## Расписание (Schedule)

### Серийное (Serial) расписание
- Транзакции выполняются **последовательно**
- Гарантирует правильность, но **низкая производительность**

### Сериализуемое расписание
- Результат эквивалентен **какому-то** серийному порядку
- Позволяет параллельное выполнение с сохранением правильности

## Двухфазная блокировка (2PL)

### Фазы
1. **Растущая фаза** — транзакция запрашивает блокировки (Shared/Exclusive)
2. **Сжимающая фаза** — транзакция освобождает блокировки и не запрашивает новые

### Гарантия
- 2PL **гарантирует** seriализуемость расписаний

### Типы блокировок

| Блокировка | Обозначение | Описание |
|------------|-------------|----------|
| Shared (S) | Читать | Разрешает чтение, не изменение |
| Exclusive (X) | Писать | Разрешает чтение и изменение |

### Проблемы 2PL
- **Тупик (deadlock)** — циклическое ожидание блокировок
- **Громоздкие блокировки** — транзакция держит все блокировки до конца

## Дополнительные механизмы
- **Timestamp Ordering** — порядок определяется временными метками
- **Multiversion Concurrency Control (MVCC)** — хранение нескольких версий данных
- **Optimistic Concurrency Control** — проверка конфликтов только при COMMIT

## Виды зависимостей, вызываемых параллельным выполнением
| Зависимость | Описание |
|-------------|----------|
| Lost Update | Одна транзакция перезаписывает результат другой |
| Dirty Read | Чтение незафиксированного изменения |
| Non-repeatable Read | Повторное чтение даёт разные данные |
| Phantom Read | Набор строк изменяется между чтениями |
