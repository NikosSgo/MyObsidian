# Подзапросы в SQL

## Определение
**Подзапрос (subquery)** — SELECT-выражение внутри другого SQL-запроса.

## По месту использования

### В WHERE
```sql
SELECT * FROM employees
WHERE dept_id = (SELECT id FROM departments WHERE name = 'IT');
```

### В FROM (производная таблица)
```sql
SELECT avg_salary FROM (
    SELECT dept_id, AVG(salary) AS avg_salary
    FROM employees GROUP BY dept_id
) AS dept_avg;
```

### В SELECT
```sql
SELECT name, (SELECT COUNT(*) FROM orders WHERE orders.user_id = users.id) AS order_count
FROM users;
```

## По количеству строк

### Однострочный (Scalar Subquery)
```sql
-- Возвращает одно значение
SELECT * FROM employees
WHERE salary > (SELECT AVG(salary) FROM employees);
```

### Многострочный
```sql
-- Возвращает столбец значений
SELECT * FROM employees
WHERE dept_id IN (SELECT id FROM departments WHERE location = 'Москва');
```

## Операторы для многострочных

| Оператор | Описание |
|----------|----------|
| `IN` | Значение присутствует в наборе |
| `NOT IN` | Значение отсутствует в наборе |
| `ANY` / `SOME` | Хотя бы одно значение (с `<`, `>`) |
| `ALL` | Все значения (с `<`, `>`) |

```sql
-- ANY: > хотя бы одного
WHERE salary > ANY (SELECT salary FROM employees WHERE dept = 'Sales')

-- ALL: > всех
WHERE salary > ALL (SELECT salary FROM employees WHERE dept = 'Sales')
```

## EXISTS / NOT EXISTS
```sql
-- Есть ли заказы у пользователя
SELECT * FROM users u
WHERE EXISTS (SELECT 1 FROM orders o WHERE o.user_id = u.id);

-- Пользователи без заказов
SELECT * FROM users u
WHERE NOT EXISTS (SELECT 1 FROM orders o WHERE o.user_id = u.id);
```

## Коррелированные подзапросы (Correlated)
- Ссылаются на **внешний запрос**
- Выполняются **для каждой строки** внешнего запроса
```sql
SELECT e.name, e.salary
FROM employees e
WHERE e.salary > (SELECT AVG(salary) FROM employees WHERE dept_id = e.dept_id);
```

## Производительность

### Советы
1. **IN vs EXISTS:** EXISTS часто быстрее для больших подзапросов
2. **NOT IN vs NOT EXISTS:** NOT EXISTS надёжнее (NULL-ы в IN могут давать неожиданные результаты)
3. **Коррелированные** подзапросы могут быть медленными → предпочитать JOIN
4. **Проверить план** выполнения: `EXPLAIN SELECT ...`

### Когда использовать подзапросы
- Простые фильтрации на основе агрегатов
- Проверка существования (EXISTS)
- Вычисления в SELECT

### Когда предпочитать JOIN
- Соединение нескольких таблиц
- Коррелированные подзапросы в WHERE (замена на JOIN)
- Сложная логика с GROUP BY
