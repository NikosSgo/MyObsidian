# Экзамен. ACID, CAP, BASE

## ACID (свойства транзакций)

**Транзакция** — логическая единица работы с БД, состоящая из одного или нескольких запросов.

### Atomicity (атомарность)
- Транзакция выполняется **полностью или не выполняется вообще**
- При ошибке — **откат** (ROLLBACK) всех изменений
- Пример: банковский перевод — списание и зачисление **вместе**

### Consistency (согласованность)
- После транзакции БД остаётся в **валидном** состоянии
- Все ограничения (constraints, triggers) остаются соблюдёнными
- Пример: сумма денег на счетах **не меняется** после перевода

### Isolation (изоляция)
- Параллельные транзакции **не влияют** друг на друга
- Реализация через **уровни изоляции** (Read Uncommitted → Serializable)
- Пример: два одновременных списания не должны превысить баланс

### Durability (долговечность)
- После COMMIT изменения **сохраняются** навсегда
- Реализация через **WAL** (Write-Ahead Logging), журнал транзакций
- Пример: после подтверждения перевода данные не теряются при аварии

## CAP Theorem (теорема Кэпа)

В распределённой системе можно обеспечить только **2 из 3**:

| Свойство | Описание |
|----------|----------|
| **C** (Consistency) | Все узлы видят **одни и те же** данные в одно время |
| **A** (Availability) | Каждый запрос получает **ответ** (без ошибки) |
| **P** (Partition Tolerance) | Система работает при **разрыве сети** между узлами |

### Компромиссы

| Система | Выбор                      | Описание                      |
| ------- | -------------------------- | ----------------------------- |
| **CP**  | Consistency + Partition    | MongoDB, HBase, Redis         |
| **AP**  | Availability + Partition   | Cassandra, DynamoDB, CouchDB  |
| **CA**  | Consistency + Availability | PostgreSQL, MySQL (один узел) |

> В распределённых системах P **обязателен** (сеть ненадёжна), поэтому выбор между C и A.

## BASE (альтернатива ACID)

**BASE** = Basically Available + Soft State + Eventually Consistent

| Свойство                  | Описание                                                                         |
| ------------------------- | -------------------------------------------------------------------------------- |
| **Basically Available**   | Система **в целом доступна**, но отдельные операции могут быть недоступны        |
| **Soft State**            | Состояние может **меняться** даже без ввода данных (репликация)                  |
| **Eventually Consistent** | При **отсутствии обновлений** все узлы в конечном счёте придут к согласованности |

### ACID vs BASE

| Критерий        | ACID                              | BASE                          |
| --------------- | --------------------------------- | ----------------------------- |
| Философия       | **Консервативная** (безопасность) | **Либеральная** (доступность) |
| Согласованность | Строгая, сразу                    | Отложенная (eventual)         |
| Скорость        | Медленнее (блокировки)            | Быстрее (нет блокировок)      |
| Масштабирование | Вертикальное                      | Горизонтальное                |
| Пример          | Банки, больницы                   | Соцсети, кэши, логи           |

## OLAP vs OLTP

| Параметр          | OLTP                              | OLAP                            |
| ----------------- | --------------------------------- | ------------------------------- |
| **Назначение**    | Транзакции (INSERT/UPDATE/DELETE) | Аналитика (SELECT с агрегацией) |
| **Запросы**       | Много коротких                    | Мало сложных                    |
| **Данные**        | Актуальные (мало записей)         | Исторические (миллионы записей) |
| **Нормализация**  | 3NF (3я нормальная форма)         | Denormalized (звезда/снежинка)  |
| **Индексы**       | B-tree, hash                      | Column-store, bitmap            |
| **Пример**        | Система заказов                   | Отчёт продаж за квартал         |
| **Схема**         | ER-диаграмма                      | Куб (мера + измерения)          |
| **Время отклика** | Миллисекунды                      | Секунды–минуты                  |

## Сравнение подходов

| Сценарий | Подход |
|----------|--------|
| Банковские транзакции | ACID + OLTP |
| Социальная сеть (лента) | BASE + AP |
| Данные warehouse | ACID + OLAP |
| IoT / Big Data | BASE + AP + OLAP |
