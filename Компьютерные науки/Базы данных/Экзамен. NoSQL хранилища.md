# Экзамен. NoSQL хранилища

## Мотивация перехода к NoSQL

- **Горизонтальное масштабирование** — добавление узлов вместо апгрейда одного сервера (scale-out vs scale-up)
- **Гибкость схемы** — нет фиксированного SQL-スキー�ма; данные могут быть вложены, вариативны по структуре
- **Высокая доступность** — отказоустойчивость через репликацию, работа при отказе отдельных узлов
- **Высокая производительность** — оптимизация под конкретные паттерны доступа (чтение/запись)
- **Проблема ORM** — несовпадение реляционной модели с объектной (impedance mismatch)

## Классификация NoSQL

### Key-Value (Ключ-Значение)

| Свойство | Описание |
|----------|----------|
| Модель | Простое хранилище пар `ключ → значение` |
| Примеры | **Redis** (in-memory, структуры данных), **DynamoDB** (AWS, автоматическое масштабирование) |
| Плюсы | Максимальная скорость чтения/записи O(1), простота |
| Минусы | Нет запросов по значениям, нет агрегации |
| Применение | Кэширование сессий, пользовательские профили, микросервисы |

### Document (Документные)

| Свойство | Описание |
|----------|----------|
| Модель | JSON/BSON-документы с вложенными структурами |
| Примеры | **MongoDB** (агрегации, индексы), **CouchDB** (HTTP API, репликация) |
| Плюсы | Естественное отображение объектов, схема-на лету, индексы по вложенным полям |
| Минусы | Дублирование данных, сложные транзакции |
| Применение | CMS, каталоги товаров, логи, IoT |

### Column-family (Столбцовые)

| Свойство | Описание |
|----------|----------|
| Модель | Данные组织ены по строковым семействам столбцов |
| Примеры | **Cassandra** (peer-to-peer, CQL), **HBase** (на HDFS, mạnhий) |
| Плюсы | Эффективные запросы по диапазонам строк, сжатие столбцов, масштабирование |
| Минусы | Сложность проектирования, ограничения на обновления |
| Применение | Аналитика больших данных, временные ряды, метрики |

### Graph (Графовые)

| Свойство | Описание |
|----------|----------|
| Модель | Узлы, рёбра, свойства; граф как первая структура |
| Примеры | **Neo4j** (Cypher), **ArangoDB** (AQL, мульти-модель) |
| Плюсы | Быстрый обход связей (O(1) по рёбрам), естественное моделирование отношений |
| Минусы | Плохое масштабирование по узлам, нет стандартного языка |
| Применение | Социальные сети, рекомендательные системы, фрод-детекция, знаниевые графы |

## Сравнение типов

| Тип | Производительность | Гибкость | Транзакции | Масштабируемость |
|-----|-------------------|----------|------------|-----------------|
| Key-Value | Максимальная | Низкая | Нет | Горизонтальная |
| Document | Высокая | Высокая | Базовые | Горизонтальная |
| Column-family | Высокая | Средняя | Ограниченные | Горизонтальная |
| Graph | Высокая (связи) | Высокая | Ограниченные | Вертикальная |

## CAP-теорема (напоминание)

NoSQL-системы выбирают 2 из 3: **Consistency**, **Availability**, **Partition tolerance**:
- **CP** — Cassandra (при настройке consistency=ALL), HBase
- **AP** — Cassandra (по умолчанию), CouchDB, DynamoDB
- **CA** — только сеть без分区 (на практике не реализуемо)
