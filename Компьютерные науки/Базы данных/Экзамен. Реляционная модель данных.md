### Реляционная модель данных

**Определение:** данные представлены в виде отношений (таблиц). Предложена Э. Коддом (1970).

**Отношение** — подмножество декартова произведения доменов: $R \subseteq D_1 \times D_2 \times ... \times D_n$.

**Свойства отношений:**
- Каждый атрибут имеет уникальное имя (столбец)
- Кортежи неупорядочены (строки)
- Атрибуты атомарны (1НФ — нет вложенных таблиц)
- Все кортежи уникальны (нет дубликатов строк)

---

### Ключи

**Первичный ключ (Primary Key)** — один или несколько атрибутов, однозначно идентифицирующих кортеж. Обязателен, уникален, NOT NULL.

**Альтернативный ключ (Alternate Key)** — любой другой атрибут/набор, который мог бы быть первичным ключом (Unique constraint).

**Суррогатный ключ (Surrogate Key)** — искусственный, не имеющий бизнес-смысла (например, `id INT AUTO_INCREMENT`). Плюсы: не меняется, простой. Минусы: дополнительный столбец.

**Естественный ключ (Natural Key)** — ключ из бизнес-атрибутов (например, `email`, `passport_number`). Плюсы: имеет смысл. Минусы: может измениться.

**Внешний ключ (Foreign Key)** — атрибут, ссылающийся на первичный ключ другой таблицы. Обеспечивает ссылочную целостность.

---

### Ограничения целостности

| Тип | Описание | Пример |
|---|---|---|
| **Доменная** | Значение атрибута из допустимого домена | `age > 0` |
| **Первичного ключа** | NOT NULL + UNIQUE | `id PRIMARY KEY` |
| **Ссылочная (FK)** | Нет «висячих» ссылок | `user_id REFERENCES users(id)` |
| **Пользовательская** | Бизнес-правило (CHECK) | `CHECK (salary > 0)` |
| **NULL** | NOT NULL / допустим NULL | `name NOT NULL` |

**Пример нормализованной схемы:**
```sql
CREATE TABLE users (
    id INT PRIMARY KEY,
    email VARCHAR(255) UNIQUE NOT NULL,
    name VARCHAR(100) NOT NULL
);

CREATE TABLE orders (
    id INT PRIMARY KEY,
    user_id INT NOT NULL REFERENCES users(id),
    total DECIMAL(10,2) NOT NULL,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```
